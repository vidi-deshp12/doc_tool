# jwt

[`target/app/services/jwt.py`](target/app/services/jwt.py) is responsible for creating and verifying JSON Web Tokens used to authenticate users in the application [[target/app/services/jwt.py]]. It establishes three module-level constants that govern all tokens produced here: `JWT_SUBJECT` fixes the token's `sub` claim to `"access"`, `ALGORITHM` sets the signing algorithm to `HS256`, and `ACCESS_TOKEN_EXPIRE_MINUTES` defines a default lifetime of one week [[target/app/services/jwt.py]].

The lowest-level building block is [`create_jwt_token()`](target/app/services/jwt.py::create_jwt_token), a keyword-only function that accepts an arbitrary claims dictionary, a secret key, and an expiry duration, and returns a signed JWT string [[target/app/services/jwt.py::create_jwt_token]]. It copies the caller's claims dictionary to avoid mutation, merges in a `JWTMeta` object carrying the computed expiry timestamp and the fixed subject, and passes the combined payload to `jwt.encode` along with the secret key and the module-level `ALGORITHM` constant [[target/app/services/jwt.py::create_jwt_token]].

[`create_access_token_for_user()`](target/app/services/jwt.py::create_access_token_for_user) is the higher-level convenience wrapper intended for normal application use [[target/app/services/jwt.py::create_access_token_for_user]]. It accepts a `User` domain object and a secret key, packages the user's username into a `JWTUser` payload, and delegates to `create_jwt_token` with an expiry duration derived from the module-level `ACCESS_TOKEN_EXPIRE_MINUTES` constant [[target/app/services/jwt.py::create_access_token_for_user]].

The complementary function [`get_username_from_token()`](target/app/services/jwt.py::get_username_from_token) reverses the process: it decodes a JWT string using the same secret key and algorithm, unpacks the result into a `JWTUser` model, and returns the embedded username [[target/app/services/jwt.py::get_username_from_token]]. Two distinct error paths are handled — a `jwt.PyJWTError` (covering invalid signatures or expired tokens) is re-raised as a `ValueError` with the message `"unable to decode JWT token"`, while a `ValidationError` (covering a token whose payload does not match the expected `JWTUser` shape) is re-raised as a `ValueError` with the message `"malformed payload in token"`, with the original exception chained in both cases to preserve the root cause [[target/app/services/jwt.py::get_username_from_token]].

## create_access_token_for_user

`create_access_token_for_user` accepts a `User` object and a `secret_key` string, and returns a JWT access token as a string [[target/app/services/jwt.py::create_access_token_for_user]]. It works by constructing a `JWTUser` from the supplied user's username, serialising it to a dictionary, and forwarding that payload along with the secret key and a computed expiry duration to `create_jwt_token` [[target/app/services/jwt.py::create_access_token_for_user]]. The expiry is set using `timedelta` configured with the module-level constant `ACCESS_TOKEN_EXPIRE_MINUTES` [[target/app/services/jwt.py]]. The function has no decorators and raises no exceptions of its own [[target/app/services/jwt.py::create_access_token_for_user]].

## create_jwt_token

`create_jwt_token` is a keyword-only function that builds and returns a signed JWT string [[target/app/services/jwt.py::create_jwt_token]]. It accepts three parameters: `jwt_content`, a `Dict[str, str]` holding the claims to embed in the token; `secret_key`, a `str` used to sign the token; and `expires_delta`, a `timedelta` that controls how far in the future the token expires [[target/app/services/jwt.py::create_jwt_token]].

The function begins by copying `jwt_content` so the caller's original dictionary is not mutated [[target/app/services/jwt.py::create_jwt_token]]. It then computes an expiry timestamp by adding `expires_delta` to the current UTC time [[target/app/services/jwt.py::create_jwt_token]]. A `JWTMeta` object is constructed with that expiry and a fixed `JWT_SUBJECT` value, converted to a plain dictionary, and merged into the working copy of the claims [[target/app/services/jwt.py::create_jwt_token]]. Finally, the enriched payload is passed to `jwt.encode` together with `secret_key` and a module-level `ALGORITHM` constant, and the resulting encoded token string is returned [[target/app/services/jwt.py::create_jwt_token]].

The function carries no route-registration or authorization decorators, and it does not declare any explicitly raised exceptions [[target/app/services/jwt.py::create_jwt_token]].

## get_username_from_token

`get_username_from_token` accepts a JWT string and a secret key, and returns the username embedded in the token's payload as a plain `str` [[target/app/services/jwt.py::get_username_from_token]]. It works by calling `jwt.decode` with the provided `token` and `secret_key`, passing a fixed signing algorithm, and then unpacking the resulting dictionary into a `JWTUser` model to extract the `username` field [[target/app/services/jwt.py::get_username_from_token]]. If the library cannot verify or decode the token — for example because the signature is invalid or the token is expired — a `jwt.PyJWTError` is caught and re-raised as a `ValueError` with the message `"unable to decode JWT token"` [[target/app/services/jwt.py::get_username_from_token]]. Separately, if the decoded payload is structurally valid JWT but does not conform to the expected `JWTUser` shape, a `ValidationError` is caught and re-raised as a `ValueError` with the message `"malformed payload in token"` [[target/app/services/jwt.py::get_username_from_token]]. In both error paths the original exception is chained via `from`, preserving the root cause for debugging [[target/app/services/jwt.py::get_username_from_token]].

> **Raises:** ValueError
