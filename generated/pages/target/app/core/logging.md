# logging

[`target/app/core/logging.py`](target/app/core/logging.py) is a small bridge module whose sole purpose is to route all standard-library log records into Loguru for unified log handling [[target/app/core/logging.py]]. It defines exactly one class, [`InterceptHandler`](target/app/core/logging.py), which is a concrete subclass of `logging.Handler` and carries no Pydantic model machinery of its own [[target/app/core/logging.py::InterceptHandler]].

`InterceptHandler` expresses all of its behaviour through a single overridden method, `emit`, which accepts a `logging.LogRecord` and returns `None`, satisfying the abstract contract that `logging.Handler` requires [[target/app/core/logging.py::InterceptHandler]]. When a record arrives, `emit` first maps the record's level name to a Loguru-native level via `logger.level`; if Loguru does not recognise the name and raises a `ValueError`, it falls back to the raw integer level number as a string [[target/app/core/logging.py::InterceptHandler]]. It then walks the call stack upward past any frames whose source file belongs to the `logging` module itself, so that Loguru can attribute the event to the true call site rather than an internal logging frame [[target/app/core/logging.py::InterceptHandler]]. With the correct stack depth in hand, it calls `logger.opt` with that depth and the record's `exc_info`, then forwards the event to Loguru via `.log` using the resolved level and the message returned by `record.getMessage` [[target/app/core/logging.py::InterceptHandler]].

## InterceptHandler

[`InterceptHandler`](target/app/core/logging.py::InterceptHandler) is a concrete subclass of the standard library's `logging.Handler`, defined in [`target/app/core/logging.py`](target/app/core/logging.py) [[target/app/core/logging.py::InterceptHandler]]. It is not a Pydantic model [[target/app/core/logging.py::InterceptHandler]]. Its sole responsibility is to act as a bridge between Python's built-in logging system and Loguru, intercepting every log record emitted through the standard `logging` API and routing it into Loguru for unified handling [[target/app/core/logging.py::InterceptHandler]].

The class defines no fields of its own, inheriting whatever state `logging.Handler` provides, and its entire behaviour is expressed through a single overridden method, [`emit`](target/app/core/logging.py::InterceptHandler::emit) [[target/app/core/logging.py::InterceptHandler]]. That method accepts a `logging.LogRecord` and returns `None`, fulfilling the abstract contract required by `logging.Handler` [[target/app/core/logging.py::InterceptHandler::emit]]. It then walks the call stack, advancing past any frames whose source file belongs to the `logging` module itself, so that Loguru reports the true originating call site rather than an internal logging frame [[target/app/core/logging.py::InterceptHandler::emit]]. The method carries a `# pragma: no cover` marker, indicating it is intentionally excluded from code-coverage measurement [[target/app/core/logging.py::InterceptHandler::emit]].

### emit

The [`emit`](target/app/core/logging.py::InterceptHandler::emit) method accepts a standard `logging.LogRecord` and returns `None`, acting as the bridge that forwards every record captured by Python's built-in logging system into Loguru [[target/app/core/logging.py::InterceptHandler::emit]].

It first attempts to resolve a Loguru-native level name by calling `logger.level` with the record's level name string; if that lookup raises a `ValueError` (meaning the level is unknown to Loguru), it falls back to the raw integer level number converted to a string via `str` [[target/app/core/logging.py::InterceptHandler::emit]].

Next, it walks the call stack by retrieving the current frame with `logging.currentframe` and incrementing a depth counter for each frame whose source file belongs to the standard `logging` module itself, using `cast` to satisfy type-checking while traversing `f_back` pointers [[target/app/core/logging.py::InterceptHandler::emit]]. This stack-walking ensures that Loguru reports the true originating call site rather than an internal logging frame [[target/app/core/logging.py::InterceptHandler::emit]].

Finally, it calls `logger.opt` with the computed `depth` and the record's `exc_info` for exception chaining, then invokes `.log` with the resolved level and the message produced by `record.getMessage`, so Loguru receives the event with full context and the correct source location [[target/app/core/logging.py::InterceptHandler::emit]]. The method is marked `# pragma: no cover`, indicating it is intentionally excluded from code-coverage measurement [[target/app/core/logging.py::InterceptHandler::emit]]. It is defined as a concrete override within the [`InterceptHandler`](target/app/core/logging.py::InterceptHandler) class, fulfilling the abstract contract of `logging.Handler` [[target/app/core/logging.py::InterceptHandler]].
