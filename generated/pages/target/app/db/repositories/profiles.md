# profiles

This module defines the `ProfilesRepository` class and a `UserLike` type alias, forming the dedicated data-access layer for user profiles and follower relationships [[target/app/db/repositories/profiles.py]]. The `UserLike` alias unions `User` and `Profile`, allowing methods throughout the file to accept either domain type interchangeably [[target/app/db/repositories/profiles.py]].

`ProfilesRepository` inherits from `BaseRepository` and serves as the single point of access for all profile reads and follow-graph mutations in the database layer [[target/app/db/repositories/profiles.py::ProfilesRepository]]. Its constructor takes an `asyncpg` `Connection`, passes it up to the parent class, and also constructs an internal `UsersRepository` instance stored as `self._users_repo`, so that user-level lookups are available without duplicating connection management [[target/app/db/repositories/profiles.py::ProfilesRepository]].

The `get_profile_by_username` method ties the class together: it delegates the raw user lookup to `self._users_repo`, assembles a `Profile` from the returned record's `username`, `bio`, and `image` fields, and — when a `requested_user` is supplied — populates the `following` field by calling `is_user_following_for_another_user` on the same repository instance [[target/app/db/repositories/profiles.py::ProfilesRepository]]. The `is_user_following_for_another_user` method handles that follow-status check by forwarding `requested_user.username` as the follower and `target_user.username` as the followee to a named SQL query, then returning the boolean `"is_following"` value from its result [[target/app/db/repositories/profiles.py::ProfilesRepository]].

Mutating the follow graph is handled by the symmetric pair `add_user_into_followers` and `remove_user_from_followers`, both of which accept `target_user` and `requested_user` as keyword-only `UserLike` arguments [[target/app/db/repositories/profiles.py::ProfilesRepository]]. `add_user_into_followers` opens a database transaction and calls the `subscribe_user_to_another` query to record the relationship, while `remove_user_from_followers` opens a transaction and calls `unsubscribe_user_from_another` to delete it, both returning `None` [[target/app/db/repositories/profiles.py::ProfilesRepository]].

## ProfilesRepository

`ProfilesRepository` is a database repository class responsible for all profile-related persistence operations, including fetching user profiles and managing follower relationships [[target/app/db/repositories/profiles.py::ProfilesRepository]]. It inherits from `BaseRepository`, placing it within the standard repository hierarchy used across the data-access layer [[target/app/db/repositories/base.py::BaseRepository]]. It is not a Pydantic model.

The constructor accepts a single `conn` argument typed as `Connection`, forwards it to the parent via `super().__init__(conn)`, and additionally constructs an internal `UsersRepository` instance stored as `self._users_repo`, making user-level queries available without duplicating connection management [[target/app/db/repositories/profiles.py::ProfilesRepository::__init__]]. There are no declared class-level fields beyond what `BaseRepository` provides; the only instance attribute introduced here is `self._users_repo` [[target/app/db/repositories/profiles.py::ProfilesRepository::__init__]] [[target/app/db/repositories/profiles.py::ProfilesRepository]].

The `get_profile_by_username` method accepts a required `username` string and an optional `requested_user` of type `UserLike`, delegates the underlying user lookup to `self._users_repo`, assembles a `Profile` object from the returned record's `username`, `bio`, and `image` fields, and — when a `requested_user` is present — also populates the `following` field by calling `is_user_following_for_another_user` [[target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username]].

The `is_user_following_for_another_user` method accepts `target_user` and `requested_user`, both typed as `UserLike`, and returns a `bool` by delegating to a named query that receives `requested_user.username` as `follower_username` and `target_user.username` as `following_username`, then surfaces the `"is_following"` field from the result [[target/app/db/repositories/profiles.py::ProfilesRepository::is_user_following_for_another_user]].

The `add_user_into_followers` method accepts the same `target_user` and `requested_user` keyword arguments, opens an atomic database transaction, and calls the `subscribe_user_to_another` query with `requested_user.username` as the follower and `target_user.username` as the account being followed, returning `None` [[target/app/db/repositories/profiles.py::ProfilesRepository::add_user_into_followers]]. Symmetrically, `remove_user_from_followers` opens a transaction and calls the `unsubscribe_user_from_another` query with the same argument mapping, atomically deleting the follow record and returning `None` [[target/app/db/repositories/profiles.py::ProfilesRepository::remove_user_from_followers]]. Together, these four methods make `ProfilesRepository` the single point of access for profile reads and follow-graph mutations in the data layer [[target/app/db/repositories/profiles.py::ProfilesRepository]].

### add_user_into_followers

`add_user_into_followers` is an asynchronous method on the `ProfilesRepository` class that records a follow relationship between two users [[target/app/db/repositories/profiles.py::ProfilesRepository::add_user_into_followers]]. It accepts two keyword-only arguments, `target_user` and `requested_user`, both typed as `UserLike`, and returns `None` [[target/app/db/repositories/profiles.py::ProfilesRepository::add_user_into_followers]]. The method opens a database transaction via `self.connection.transaction()` to ensure the operation is atomic, then calls `queries.subscribe_user_to_another` with the shared connection, passing `requested_user.username` as the follower and `target_user.username` as the account being followed [[target/app/db/repositories/profiles.py::ProfilesRepository::add_user_into_followers]]. In other words, `requested_user` is the one who initiates the follow action, and `target_user` is the one whose follower list grows as a result [[target/app/db/repositories/profiles.py::ProfilesRepository::add_user_into_followers]]. No exceptions are explicitly raised by this method, and its sole side effect is the insertion of the subscription record within the transaction [[target/app/db/repositories/profiles.py::ProfilesRepository]].

### get_profile_by_username

`get_profile_by_username` is an asynchronous method on [`ProfilesRepository`](target/app/db/repositories/profiles.py::ProfilesRepository) that retrieves a user's public profile by their username and returns a [`Profile`](target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username) object [[target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username]]. It accepts two keyword-only arguments: `username`, a required string identifying the user to look up, and `requested_user`, an optional `UserLike` representing the currently authenticated caller (or `None` for unauthenticated requests) [[target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username]].

The method first delegates to `self._users_repo.get_user_by_username` to fetch the underlying user record from the database [[target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username]]. It then constructs a `Profile` instance populated with `username`, `bio`, and `image` taken directly from that user record [[target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username]]. When `requested_user` is provided, the method additionally calls `self.is_user_following_for_another_user` to determine whether the requesting user follows the looked-up user, and sets the `following` field on the profile accordingly [[target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username]]. The fully populated `Profile` is then returned to the caller [[target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username]].

### is_user_following_for_another_user

`is_user_following_for_another_user` is an asynchronous method on the `ProfilesRepository` class that checks whether one user is following another and returns a `bool` result [[target/app/db/repositories/profiles.py::ProfilesRepository::is_user_following_for_another_user]]. It accepts two keyword-only arguments, `target_user` and `requested_user`, both typed as `UserLike`, where `requested_user` represents the potential follower and `target_user` represents the account being followed [[target/app/db/repositories/profiles.py::ProfilesRepository::is_user_following_for_another_user]]. The method delegates entirely to `queries.is_user_following_for_another`, passing `self.connection` along with the `username` attributes extracted from each argument as `follower_username` and `following_username` [[target/app/db/repositories/profiles.py::ProfilesRepository::is_user_following_for_another_user]]. It returns the `"is_following"` field from the query result, surfacing it directly as the method's `bool` return value [[target/app/db/repositories/profiles.py::ProfilesRepository::is_user_following_for_another_user]]. Being `async`, it must be awaited by the caller, consistent with the repository's database-access pattern [[target/app/db/repositories/profiles.py::ProfilesRepository]].

### remove_user_from_followers

`remove_user_from_followers` is an asynchronous method on the `ProfilesRepository` class that removes a follow relationship between two users [[target/app/db/repositories/profiles.py::ProfilesRepository::remove_user_from_followers]]. It accepts two keyword-only arguments, `target_user` and `requested_user`, both typed as `UserLike`, and returns `None` [[target/app/db/repositories/profiles.py::ProfilesRepository::remove_user_from_followers]]. The method opens a database transaction via `self.connection.transaction()` and, within that transaction, calls `queries.unsubscribe_user_from_another`, passing `requested_user.username` as the `follower_username` and `target_user.username` as the `following_username` [[target/app/db/repositories/profiles.py::ProfilesRepository::remove_user_from_followers]]. This means `requested_user` is the account that was following, and `target_user` is the account being unfollowed [[target/app/db/repositories/profiles.py::ProfilesRepository::remove_user_from_followers]]. Wrapping the query in a transaction ensures the unsubscription is applied atomically, rolling back automatically if the underlying operation fails [[target/app/db/repositories/profiles.py::ProfilesRepository::remove_user_from_followers]]. The method belongs to `ProfilesRepository`, which centralises profile-related database access [[target/app/db/repositories/profiles.py::ProfilesRepository]].
