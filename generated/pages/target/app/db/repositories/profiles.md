# profiles

This module is the data-access layer for user profiles and follow relationships in the application [[target/app/db/repositories/profiles.py]]. It defines a single type alias, `UserLike`, which is a union of `User` and `Profile`, and one class, `ProfilesRepository`, which is the sole exported unit of behaviour [[target/app/db/repositories/profiles.py::ProfilesRepository]].

`ProfilesRepository` inherits from `BaseRepository` and concentrates every database interaction that concerns profiles and the social graph of follow connections [[target/app/db/repositories/profiles.py::ProfilesRepository]]. Its constructor accepts an asyncpg `Connection`, forwards it to the parent class through `super().__init__(conn)`, and additionally spins up an internal `UsersRepository` stored as `self._users_repo` on the same connection, giving the class access to user-level lookups without requiring a second connection to be supplied from outside [[target/app/db/repositories/profiles.py::ProfilesRepository]].

The four async methods on the class divide cleanly into one read method and three follow-management methods. `get_profile_by_username` is the primary read path: given a username string and an optional `requested_user`, it resolves the target through `self._users_repo`, assembles a `Profile` from the retrieved `username`, `bio`, and `image` fields, and, when a `requested_user` is present, fills the `profile.following` boolean by delegating to `is_user_following_for_another_user` [[target/app/db/repositories/profiles.py::ProfilesRepository]]. When `requested_user` is absent, that extra query is skipped entirely and `following` remains at its default [[target/app/db/repositories/profiles.py::ProfilesRepository]].

`is_user_following_for_another_user` is a focused, side-effect-free helper that both supports `get_profile_by_username` and is callable on its own [[target/app/db/repositories/profiles.py::ProfilesRepository]]. It accepts `target_user` and `requested_user` as keyword-only `UserLike` arguments, calls `queries.is_user_following_for_another` directly, and returns the `"is_following"` boolean extracted from the result with no additional branching [[target/app/db/repositories/profiles.py::ProfilesRepository]].

The two write methods, `add_user_into_followers` and `remove_user_from_followers`, are mirror images of each other [[target/app/db/repositories/profiles.py::ProfilesRepository]]. Both accept the same `target_user`/`requested_user` keyword pair, wrap their work in an atomic `self.connection.transaction()` block, and return `None` [[target/app/db/repositories/profiles.py::ProfilesRepository]]. `add_user_into_followers` delegates the insertion to `queries.subscribe_user_to_another`, while `remove_user_from_followers` delegates the deletion to `queries.unsubscribe_user_from_another`, keeping the SQL entirely out of the repository body [[target/app/db/repositories/profiles.py::ProfilesRepository]].

## ProfilesRepository

`ProfilesRepository` is a class defined in [`target/app/db/repositories/profiles.py`](target/app/db/repositories/profiles.py) that handles all database interactions related to user profiles and follow relationships [[target/app/db/repositories/profiles.py::ProfilesRepository]]. It is not a Pydantic model; it is a plain Python class that inherits from `BaseRepository` [[target/app/db/repositories/base.py::BaseRepository]] [[target/app/db/repositories/profiles.py::ProfilesRepository]].

The constructor accepts a `Connection` argument and passes it up to the parent class via `super().__init__(conn)`, ensuring the base repository is properly initialised [[target/app/db/repositories/profiles.py::ProfilesRepository::__init__]]. Beyond the inherited setup, `__init__` also creates an internal `UsersRepository` instance — stored as `self._users_repo` — using the same connection, making user-level data access available internally without a separate connection [[target/app/db/repositories/profiles.py::ProfilesRepository::__init__]]. The only instance field introduced by this class is therefore `self._users_repo`; the connection itself is held by the inherited base [[target/app/db/repositories/profiles.py::ProfilesRepository::__init__]] [[target/app/db/repositories/base.py::BaseRepository]].

`get_profile_by_username` is an asynchronous method that takes a `username` string and an optional `requested_user` of type `UserLike`, and returns a `Profile` [[target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username]]. It resolves the target user through `self._users_repo`, constructs a `Profile` from the user's `username`, `bio`, and `image` fields, and — if `requested_user` is provided — populates the `profile.following` boolean by calling `is_user_following_for_another_user` [[target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username]]. When `requested_user` is absent or `None`, the `following` field is left at its default and no follow-state query is issued [[target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username]].

`is_user_following_for_another_user` is a focused, read-only asynchronous method that checks whether one user follows another and returns a `bool` [[target/app/db/repositories/profiles.py::ProfilesRepository::is_user_following_for_another_user]]. Both `target_user` and `requested_user` are keyword-only parameters of type `UserLike`; the method delegates directly to `queries.is_user_following_for_another`, extracts the `"is_following"` key from the result, and returns it with no branching logic or side effects [[target/app/db/repositories/profiles.py::ProfilesRepository::is_user_following_for_another_user]].

`add_user_into_followers` is an asynchronous method that records a new follow relationship between two `UserLike` arguments — `requested_user` as the follower and `target_user` as the account being followed — returning `None` [[target/app/db/repositories/profiles.py::ProfilesRepository::add_user_into_followers]]. The write is wrapped in a database transaction opened via `self.connection.transaction()` to guarantee atomicity, and the actual insertion is performed by `queries.subscribe_user_to_another` [[target/app/db/repositories/profiles.py::ProfilesRepository::add_user_into_followers]].

`remove_user_from_followers` mirrors that design for the inverse operation: it removes an existing follow record between the same pair of `UserLike` parameters, again inside an atomic transaction, this time delegating to `queries.unsubscribe_user_from_another` [[target/app/db/repositories/profiles.py::ProfilesRepository::remove_user_from_followers]]. Like `add_user_into_followers`, it returns `None` and raises no exceptions of its own [[target/app/db/repositories/profiles.py::ProfilesRepository::remove_user_from_followers]].

### add_user_into_followers

`add_user_into_followers` is an asynchronous method on `ProfilesRepository` that records a follow relationship between two users, returning nothing on completion [[target/app/db/repositories/profiles.py::ProfilesRepository::add_user_into_followers]]. It accepts two keyword-only arguments — `target_user` and `requested_user`, both typed as `UserLike` — where `requested_user` represents the account initiating the follow and `target_user` represents the account being followed [[target/app/db/repositories/profiles.py::ProfilesRepository::add_user_into_followers]]. The entire operation is wrapped in a database transaction opened via `self.connection.transaction()`, ensuring the write is atomic [[target/app/db/repositories/profiles.py::ProfilesRepository::add_user_into_followers]]. Within that transaction, it delegates to `queries.subscribe_user_to_another`, passing the active connection along with `follower_username` resolved from `requested_user.username` and `following_username` resolved from `target_user.username` [[target/app/db/repositories/profiles.py::ProfilesRepository::add_user_into_followers]]. No value is returned and no exceptions are explicitly raised by this method itself [[target/app/db/repositories/profiles.py::ProfilesRepository::add_user_into_followers]].

### get_profile_by_username

`get_profile_by_username` is an asynchronous method on `ProfilesRepository` that retrieves a public profile for a given username and optionally enriches it with follow-state for a requesting user [[target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username]].

It accepts two keyword-only arguments: `username`, a `str` identifying the account to look up, and `requested_user`, an `Optional[UserLike]` representing the currently authenticated user making the request — which may be `None` for unauthenticated callers [[target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username]]. It returns a `Profile` object [[target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username]].

The method first delegates user resolution to `self._users_repo.get_user_by_username`, passing the `username` argument through [[target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username]]. It then constructs a `Profile` from the resolved user's `username`, `bio`, and `image` fields [[target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username]]. If `requested_user` is provided and truthy, the method calls `self.is_user_following_for_another_user` with the resolved user as `target_user` and the caller as `requested_user`, and assigns the boolean result to `profile.following` [[target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username]]. When `requested_user` is absent or `None`, the `following` field is left at its default and no follow-state query is issued [[target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username]]. The fully populated `Profile` is then returned to the caller [[target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username]].

### is_user_following_for_another_user

`is_user_following_for_another_user` is an asynchronous method on [`ProfilesRepository`](target/app/db/repositories/profiles.py::ProfilesRepository) that checks whether one user is following another and returns a `bool` [[target/app/db/repositories/profiles.py::ProfilesRepository::is_user_following_for_another_user]]. It accepts two keyword-only arguments, `target_user` and `requested_user`, both typed as `UserLike`, where `requested_user` represents the potential follower and `target_user` represents the account being followed [[target/app/db/repositories/profiles.py::ProfilesRepository::is_user_following_for_another_user]]. Internally, it delegates to `queries.is_user_following_for_another`, passing `self.connection` along with the `follower_username` and `following_username` derived from the respective users' `username` attributes [[target/app/db/repositories/profiles.py::ProfilesRepository::is_user_following_for_another_user]]. The result of that query is a mapping from which the `"is_following"` key is extracted and returned directly as the method's `bool` return value [[target/app/db/repositories/profiles.py::ProfilesRepository::is_user_following_for_another_user]]. The method is a straightforward, single-purpose database read with no branching logic, no side effects, and no exceptions explicitly raised [[target/app/db/repositories/profiles.py::ProfilesRepository::is_user_following_for_another_user]].

### remove_user_from_followers

`remove_user_from_followers` is an asynchronous method on `ProfilesRepository` that removes a follow relationship between two users [[target/app/db/repositories/profiles.py::ProfilesRepository::remove_user_from_followers]]. It accepts two keyword-only arguments, `target_user` and `requested_user`, both typed as `UserLike`, and returns `None` [[target/app/db/repositories/profiles.py::ProfilesRepository::remove_user_from_followers]]. The method opens a database transaction via `self.connection.transaction()` to ensure the removal is atomic [[target/app/db/repositories/profiles.py::ProfilesRepository::remove_user_from_followers]]. Within that transaction, it calls `queries.unsubscribe_user_from_another`, passing the shared connection along with `follower_username` mapped to `requested_user.username` and `following_username` mapped to `target_user.username`, which performs the actual deletion of the follow record [[target/app/db/repositories/profiles.py::ProfilesRepository::remove_user_from_followers]]. No exceptions are explicitly raised by the method itself, and it defines no return value beyond `None` [[target/app/db/repositories/profiles.py::ProfilesRepository::remove_user_from_followers]].
