# profiles

The module [`target/app/db/repositories/profiles.py`](target/app/db/repositories/profiles.py) defines the data-access layer for user profiles and follower relationships within the application [[target/app/db/repositories/profiles.py]]. It introduces a `UserLike` type alias that accepts either a `User` or a `Profile` object, providing a flexible parameter type for the follow-management methods that follow [[target/app/db/repositories/profiles.py]].

The single class defined here, `ProfilesRepository`, is a database repository responsible for all profile and follower operations, inheriting its connection-management infrastructure from `BaseRepository` [[target/app/db/repositories/profiles.py::ProfilesRepository]]. At construction time it delegates to the parent via `super().__init__(conn)` and immediately creates an internal `UsersRepository` bound to the same connection, stored as `self._users_repo`, so that profile lookups can cross-reference user records without opening a second database connection [[target/app/db/repositories/profiles.py::ProfilesRepository]].

Four public async methods make up the repository's interface [[target/app/db/repositories/profiles.py::ProfilesRepository]]. `get_profile_by_username` retrieves a user through `self._users_repo` and assembles a `Profile` populated with `username`, `bio`, and `image`; when an optional `requested_user` argument is provided it additionally resolves the `following` field by calling `is_user_following_for_another_user` [[target/app/db/repositories/profiles.py::ProfilesRepository]]. `is_user_following_for_another_user` issues a database query with both users' usernames and returns the `"is_following"` boolean from the result, forming the shared primitive that `get_profile_by_username` depends on [[target/app/db/repositories/profiles.py::ProfilesRepository]]. `add_user_into_followers` wraps `queries.subscribe_user_to_another` in an atomic transaction to persist a follow relationship, accepting both participants as keyword-only `UserLike` arguments [[target/app/db/repositories/profiles.py::ProfilesRepository]]. `remove_user_from_followers` mirrors that operation by executing `queries.unsubscribe_user_from_another` inside a transaction to atomically delete the corresponding follow record [[target/app/db/repositories/profiles.py::ProfilesRepository]].

## ProfilesRepository

`ProfilesRepository` is a database repository class responsible for managing user profile data and follower relationships, defined in [`target/app/db/repositories/profiles.py`](target/app/db/repositories/profiles.py) [[target/app/db/repositories/profiles.py::ProfilesRepository]]. It is not a Pydantic model. It inherits directly from `BaseRepository` [[target/app/db/repositories/base.py::BaseRepository]], extending the base connection-management infrastructure for profile-specific operations [[target/app/db/repositories/profiles.py::ProfilesRepository]].

During initialisation, the constructor delegates connection setup to the parent class via `super().__init__(conn)` and then creates an internal `UsersRepository` instance bound to the same connection, storing it as `self._users_repo` so that profile operations can cross-reference user data without opening a separate connection [[target/app/db/repositories/profiles.py::ProfilesRepository::__init__]].

The class exposes four public async methods. `get_profile_by_username` looks up a user record through `self._users_repo` and assembles a `Profile` object populated with the user's `username`, `bio`, and `image`; when an optional `requested_user` argument is supplied it also resolves the `following` field by delegating to `is_user_following_for_another_user` [[target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username]]. `is_user_following_for_another_user` queries the database with the two users' usernames and returns the `"is_following"` boolean extracted directly from the query result [[target/app/db/repositories/profiles.py::ProfilesRepository::is_user_following_for_another_user]]. `add_user_into_followers` persists a follow relationship inside an atomic transaction by calling `queries.subscribe_user_to_another` with the follower's and the target's usernames; both parameters are keyword-only and typed as `UserLike` [[target/app/db/repositories/profiles.py::ProfilesRepository::add_user_into_followers]]. Finally, `remove_user_from_followers` mirrors that operation in reverse, executing `queries.unsubscribe_user_from_another` inside a transaction to atomically delete the follow record between the two users [[target/app/db/repositories/profiles.py::ProfilesRepository::remove_user_from_followers]].

### __init__

Delegates connection setup to the parent repository by calling `super().__init__(conn)`, then instantiates a `UsersRepository` with the same connection and stores it as `self._users_repo` for use by profile operations that need to cross-reference user data [[target/app/db/repositories/profiles.py::ProfilesRepository::__init__]].

### add_user_into_followers

Persists a follow relationship between two users within a database transaction, making `requested_user` a follower of `target_user` [[target/app/db/repositories/profiles.py::ProfilesRepository::add_user_into_followers]]. It opens an atomic transaction via `self.connection.transaction()` before delegating to `queries.subscribe_user_to_another`, passing `requested_user.username` as the follower and `target_user.username` as the account being followed [[target/app/db/repositories/profiles.py::ProfilesRepository::add_user_into_followers]]. Both parameters are keyword-only and typed as `UserLike`, and the method belongs to `ProfilesRepository` [[target/app/db/repositories/profiles.py::ProfilesRepository]].

### get_profile_by_username

Fetches a user record by `username` via `self._users_repo.get_user_by_username` and constructs a `Profile` populated with the user's `username`, `bio`, and `image` [[target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username]]. If `requested_user` is provided, it additionally resolves the `following` field by calling `self.is_user_following_for_another_user` with the retrieved user as `target_user` and the caller's identity as `requested_user` [[target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username]]. The completed `Profile` is then returned [[target/app/db/repositories/profiles.py::ProfilesRepository::get_profile_by_username]].

### is_user_following_for_another_user

Queries the database to determine whether `requested_user` is following `target_user`, passing their usernames as named arguments alongside the repository's connection [[target/app/db/repositories/profiles.py::ProfilesRepository::is_user_following_for_another_user]]. Returns the `"is_following"` boolean field extracted directly from the query result [[target/app/db/repositories/profiles.py::ProfilesRepository::is_user_following_for_another_user]].

### remove_user_from_followers

Removes `requested_user` from the followers of `target_user` by executing the unsubscribe query within a database transaction [[target/app/db/repositories/profiles.py::ProfilesRepository::remove_user_from_followers]]. The operation runs inside `self.connection.transaction()` to ensure atomicity, and delegates the actual deletion to `queries.unsubscribe_user_from_another`, passing `requested_user.username` as the follower and `target_user.username` as the account being followed [[target/app/db/repositories/profiles.py::ProfilesRepository::remove_user_from_followers]].
