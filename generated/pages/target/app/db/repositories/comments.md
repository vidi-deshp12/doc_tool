# comments

This module provides the data-access layer for all comment-related persistence operations in the application, defining a single class that mediates between the database and the comment domain model [[target/app/db/repositories/comments.py]].

`CommentsRepository` is the sole class defined here; it inherits from `BaseRepository` and is responsible for creating, retrieving, and deleting comments [[target/app/db/repositories/comments.py::CommentsRepository]]. Its constructor accepts a `Connection`, forwards it to the parent class to initialise shared connection handling, and also creates an internal `ProfilesRepository` instance stored as `self._profiles_repo` — reflecting a deliberate design dependency, since fully hydrating a comment requires resolving its author's profile [[target/app/db/repositories/comments.py::CommentsRepository]].

The class exposes four public async methods. `get_comment_by_id` fetches a single comment scoped to a specific article by numeric ID, raising `EntityDoesNotExist` with a descriptive message when no matching row is found rather than returning `None` [[target/app/db/repositories/comments.py::CommentsRepository]]. `get_comments_for_article` retrieves all comments for a given article's slug and returns them as a list of `Comment` domain objects, accepting an optional requesting user so that each author's follow state can be resolved correctly [[target/app/db/repositories/comments.py::CommentsRepository]]. `create_comment_for_article` persists a new comment from a body string, an `Article`, and an authoring `User`, then returns the fully hydrated `Comment` [[target/app/db/repositories/comments.py::CommentsRepository]]. `delete_comment` is a thin async wrapper that delegates entirely to the underlying query, accepting a `Comment` instance and returning nothing [[target/app/db/repositories/comments.py::CommentsRepository]].

All four public methods depend on the private helper `_get_comment_from_db_record`, which assembles a `Comment` domain object from a raw database `Record` by reading the `id`, `body`, `created_at`, and `updated_at` columns directly from the row and awaiting `self._profiles_repo.get_profile_by_username` to resolve the author before construction [[target/app/db/repositories/comments.py::CommentsRepository]]. The optional `requested_user` is forwarded through this helper to the profile lookup so that follow state is always determined relative to the currently authenticated user [[target/app/db/repositories/comments.py::CommentsRepository]].

## CommentsRepository

`CommentsRepository` is a database repository class responsible for all comment-related persistence operations — creating, retrieving, and deleting comments — within the application [[target/app/db/repositories/comments.py::CommentsRepository]]. It is not a Pydantic model; it is a plain Python class that inherits from `BaseRepository` [[target/app/db/repositories/base.py::BaseRepository]] [[target/app/db/repositories/comments.py::CommentsRepository]].

The constructor accepts a `Connection` argument, passes it to the parent class via `super().__init__(conn)` to initialise shared database connection handling, and additionally instantiates a `ProfilesRepository` with the same connection, storing it as the private attribute `self._profiles_repo` [[target/app/db/repositories/comments.py::CommentsRepository::__init__]]. This internal `ProfilesRepository` reference reflects a deliberate design dependency: comment operations require profile data to fully hydrate a comment's author [[target/app/db/repositories/comments.py::CommentsRepository]] [[target/app/db/repositories/comments.py::CommentsRepository::__init__]].

The class exposes four public async methods. `get_comment_by_id` fetches a single comment by its numeric ID scoped to a specific article, raising `EntityDoesNotExist` with a descriptive message when no matching row is found rather than returning `None` [[target/app/db/repositories/comments.py::CommentsRepository::get_comment_by_id]]. `get_comments_for_article` retrieves all comments belonging to a given article's slug and returns them as a `List[Comment]`, accepting an optional requesting user to influence follow-state resolution on each author's profile [[target/app/db/repositories/comments.py::CommentsRepository::get_comments_for_article]]. `create_comment_for_article` persists a new comment row from a body string, an `Article`, and an authoring `User`, then returns the fully hydrated `Comment` domain object [[target/app/db/repositories/comments.py::CommentsRepository::create_comment_for_article]]. `delete_comment` is a thin async wrapper that delegates entirely to the underlying query call, accepting a `Comment` instance and returning `None` with no conditional logic of its own [[target/app/db/repositories/comments.py::CommentsRepository::delete_comment]].

All four public methods rely on the private helper `_get_comment_from_db_record`, which assembles a `Comment` domain object from a raw database `Record` by reading the `id`, `body`, `created_at`, and `updated_at` fields directly from the row and awaiting `self._profiles_repo.get_profile_by_username` to resolve the author's profile before construction [[target/app/db/repositories/comments.py::CommentsRepository::_get_comment_from_db_record]]. The optional `requested_user` argument is forwarded through this helper to the profile lookup so that follow state can be determined relative to the current authenticated user [[target/app/db/repositories/comments.py::CommentsRepository::_get_comment_from_db_record]].

### __init__

The `__init__` method is the constructor for the `CommentsRepository` class, accepting a single parameter `conn` of type `Connection` and returning `None` [[target/app/db/repositories/comments.py::CommentsRepository::__init__]]. It begins by delegating to the parent class constructor via `super().__init__(conn)`, passing the connection through to the base repository so that shared database connection handling is initialised [[target/app/db/repositories/comments.py::CommentsRepository::__init__]]. Following that, it instantiates a `ProfilesRepository` with the same `conn` and assigns it to the instance attribute `self._profiles_repo`, making profile-related queries available to the comments repository [[target/app/db/repositories/comments.py::CommentsRepository::__init__]]. This design means `CommentsRepository` holds a private reference to a `ProfilesRepository`, indicating that comment operations have a dependency on profile data retrieval [[target/app/db/repositories/comments.py::CommentsRepository]] [[target/app/db/repositories/comments.py::CommentsRepository::__init__]].

### _get_comment_from_db_record

`_get_comment_from_db_record` is a private asynchronous helper method on [`CommentsRepository`](target/app/db/repositories/comments.py::CommentsRepository) that assembles and returns a fully-hydrated `Comment` domain object from raw database data [[target/app/db/repositories/comments.py::CommentsRepository::_get_comment_from_db_record]]. It accepts three keyword-only arguments beyond `self`: a `Record` named `comment_row` containing the raw database row, a string `author_username` identifying the comment's author, and an optional `User` named `requested_user` representing the currently authenticated user (if any), which is forwarded to the profile lookup to determine follow state [[target/app/db/repositories/comments.py::CommentsRepository::_get_comment_from_db_record]]. The method reads `id`, `body`, `created_at`, and `updated_at` directly from `comment_row`, then performs an `await` call to `self._profiles_repo.get_profile_by_username` to resolve the author's profile before constructing the `Comment` instance [[target/app/db/repositories/comments.py::CommentsRepository::_get_comment_from_db_record]]. Because the profile fetch is itself asynchronous, the method is declared `async`, and the result is returned as a single `Comment` object [[target/app/db/repositories/comments.py::CommentsRepository::_get_comment_from_db_record]]. No decorators are applied and no exceptions are raised directly within the method body [[target/app/db/repositories/comments.py::CommentsRepository::_get_comment_from_db_record]].

### create_comment_for_article

`create_comment_for_article` is an asynchronous method on [`CommentsRepository`](target/app/db/repositories/comments.py::CommentsRepository) that persists a new comment and returns the fully hydrated domain object [[target/app/db/repositories/comments.py::CommentsRepository::create_comment_for_article]]. It accepts three keyword-only arguments — a `body` string containing the comment text, an `Article` instance identifying the article being commented on, and a `User` instance representing the comment's author — and returns a `Comment` [[target/app/db/repositories/comments.py::CommentsRepository::create_comment_for_article]].

The method first delegates to `queries.create_new_comment`, passing the repository's active database connection along with the `body`, the article's `slug`, and the user's `username`, which writes the new row to the database and returns the raw record [[target/app/db/repositories/comments.py::CommentsRepository::create_comment_for_article]]. It then passes that raw row to `self._get_comment_from_db_record`, supplying the `author_username` read directly from the returned row and the original `user` as the `requested_user`, which converts the database record into a `Comment` domain object and is the value ultimately returned to the caller [[target/app/db/repositories/comments.py::CommentsRepository::create_comment_for_article]].

### delete_comment

`delete_comment` is an asynchronous method on the [`CommentsRepository`](target/app/db/repositories/comments.py::CommentsRepository) class that removes a comment from the database [[target/app/db/repositories/comments.py::CommentsRepository::delete_comment]]. It accepts a single keyword-only argument, `comment`, typed as a `Comment` instance, and returns `None` [[target/app/db/repositories/comments.py::CommentsRepository::delete_comment]]. The method delegates entirely to `queries.delete_comment_by_id`, passing the repository's active database connection alongside the comment's own `id_` field and its author's `username` as identifying parameters [[target/app/db/repositories/comments.py::CommentsRepository::delete_comment]]. There are no decorators, no explicitly raised exceptions, and no conditional logic — the method is a thin, single-purpose async wrapper over the underlying query call [[target/app/db/repositories/comments.py::CommentsRepository::delete_comment]].

### get_comment_by_id

`get_comment_by_id` is an asynchronous method on the [`CommentsRepository`](target/app/db/repositories/comments.py::CommentsRepository) class that retrieves a single comment by its numeric ID, scoped to a specific article [[target/app/db/repositories/comments.py::CommentsRepository::get_comment_by_id]]. It accepts three keyword-only arguments — a required `comment_id: int`, a required `article: Article`, and an optional `user: Optional[User]` defaulting to `None` — and returns a `Comment` instance [[target/app/db/repositories/comments.py::CommentsRepository::get_comment_by_id]].

The method begins by awaiting `queries.get_comment_by_id_and_slug`, passing the repository's database connection along with the `comment_id` and the slug derived from the supplied `article` [[target/app/db/repositories/comments.py::CommentsRepository::get_comment_by_id]]. If a matching row is found, it is handed off to `self._get_comment_from_db_record`, which receives the raw row, the author's username extracted from that row, and the optional `requested_user` argument, with the resulting `Comment` object being returned to the caller [[target/app/db/repositories/comments.py::CommentsRepository::get_comment_by_id]].

If no matching row is returned from the database query, the method raises [`EntityDoesNotExist`](target/app/db/errors.py::EntityDoesNotExist) with a descriptive message formatted as `"comment with id {comment_id} does not exist"`, ensuring that callers can detect the missing-resource case through a typed exception rather than a `None` return [[target/app/db/errors.py::EntityDoesNotExist]] [[target/app/db/repositories/comments.py::CommentsRepository::get_comment_by_id]].

> **Raises:** EntityDoesNotExist

### get_comments_for_article

`get_comments_for_article` is an async method on [`CommentsRepository`](target/app/db/repositories/comments.py::CommentsRepository) that retrieves all comments belonging to a given article and returns them as a typed list [[target/app/db/repositories/comments.py::CommentsRepository::get_comments_for_article]]. It accepts two keyword-only arguments: a required `Article` instance and an optional `User` instance that defaults to `None`, representing the user making the request [[target/app/db/repositories/comments.py::CommentsRepository::get_comments_for_article]].

Internally, the method first executes a database query via `queries.get_comments_for_article_by_slug`, passing the repository's active connection and the article's `slug` to fetch the raw comment rows [[target/app/db/repositories/comments.py::CommentsRepository::get_comments_for_article]]. It then iterates over those rows and awaits `self._get_comment_from_db_record` for each one, supplying the raw row, the row's `author_username` field, and the optional requesting user, before collecting the results into the returned `List[Comment]` [[target/app/db/repositories/comments.py::CommentsRepository::get_comments_for_article]].
