# main

This module serves as the application entry point for the FastAPI service, defining the factory function that assembles the application and immediately invoking it to produce the module-level `app` instance [[target/app/main.py]].

The sole function defined here, `get_application`, is a factory that builds and returns a fully configured `FastAPI` application [[target/app/main.py::get_application]]. It starts by retrieving application settings and invoking logging configuration on them, so the logging setup is in place before anything else is assembled [[target/app/main.py::get_application]]. The `FastAPI` instance itself is constructed using keyword arguments sourced from those settings, keeping deployment-specific metadata and behaviour externally controlled rather than hardcoded [[target/app/main.py::get_application]].

Once the instance exists, `get_application` layers in cross-cutting concerns in sequence [[target/app/main.py::get_application]]. CORS is enabled via `CORSMiddleware`, permitting all methods and headers against the host origins declared in settings and allowing credentials [[target/app/main.py::get_application]]. Two lifecycle hooks are then registered: a startup handler and a shutdown handler, allowing the application to perform initialisation and teardown at the appropriate points in its lifecycle [[target/app/main.py::get_application]]. Dedicated exception handlers are wired up for both `HTTPException` and `RequestValidationError`, so neither HTTP errors nor validation failures fall through to FastAPI's defaults [[target/app/main.py::get_application]]. Finally, the top-level API router is mounted under the prefix defined in settings, making all routes available at the configured path, and the fully assembled application is returned [[target/app/main.py::get_application]].

The returned value is immediately assigned to the module-level name `app`, which is the object an ASGI server such as Uvicorn or Gunicorn targets when starting the service [[target/app/main.py]].

## get_application

`get_application` is a factory function that builds and returns a fully configured [`FastAPI`](target/app/main.py) application instance [[target/app/main.py::get_application]]. It begins by retrieving the current application settings and immediately invoking logging configuration on them, ensuring the logging setup is in place before the application is assembled [[target/app/main.py::get_application]]. The `FastAPI` instance is constructed using keyword arguments drawn from those settings, which allows deployment-specific metadata and behaviour to be controlled externally rather than hardcoded [[target/app/main.py::get_application]].

CORS is then enabled via `CORSMiddleware`, configured to permit all methods and headers against the host origins declared in settings, with credentials allowed [[target/app/main.py::get_application]]. Two lifecycle event handlers are registered: a startup handler produced by `create_start_app_handler` and a shutdown handler produced by `create_stop_app_handler`, which means the application can perform initialisation and teardown work at the appropriate points in its lifecycle [[target/app/main.py::get_application]]. Exception handling is wired up for both `HTTPException` and `RequestValidationError`, so HTTP errors and request validation failures each receive a dedicated handler rather than falling back to FastAPI's defaults [[target/app/main.py::get_application]]. Finally, the top-level API router is mounted under the prefix defined in settings, making all routes available at the configured path [[target/app/main.py::get_application]]. The fully assembled application is then returned to the caller [[target/app/main.py::get_application]].
