# http_error

This module is a small error-formatting layer whose sole purpose is to intercept `HTTPException` instances raised anywhere in the application and convert them into a consistently shaped JSON response [[target/app/api/errors/http_error.py]].

It defines one item: the asynchronous function `http_error_handler`, which accepts a `Request` object (ignored, conventionally named `_`) and an `HTTPException` carrying the error detail and status code [[target/app/api/errors/http_error.py::http_error_handler]]. The function returns a `JSONResponse` whose body is a JSON object with a single `"errors"` key mapped to a list containing `exc.detail`, and whose HTTP status code is taken directly from `exc.status_code` [[target/app/api/errors/http_error.py::http_error_handler]]. By wrapping the detail in a list under the `"errors"` key, the function enforces a uniform error envelope across all HTTP error responses in the application [[target/app/api/errors/http_error.py::http_error_handler]]. This handler is designed to be registered at the framework level so that every `HTTPException` raised in the application is automatically routed through this single formatting point rather than handled ad hoc at each call site [[target/app/api/errors/http_error.py]].

## http_error_handler

`http_error_handler` is an asynchronous function that converts an HTTP exception into a JSON response suitable for returning to API clients [[target/app/api/errors/http_error.py::http_error_handler]]. It accepts two parameters: an unnamed `Request` object (ignored, indicated by the `_` convention) and an `HTTPException` instance carrying the error detail and status code [[target/app/api/errors/http_error.py::http_error_handler]]. It returns a `JSONResponse` whose body is a JSON object with a single `"errors"` key mapped to a list containing `exc.detail`, and whose HTTP status code is taken directly from `exc.status_code` [[target/app/api/errors/http_error.py::http_error_handler]]. This function is intended to be registered as a framework-level exception handler so that any `HTTPException` raised anywhere in the application is automatically formatted in this consistent envelope structure [[target/app/api/errors/http_error.py]].
