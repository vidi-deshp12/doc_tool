# articles

This module is a collection of FastAPI dependency functions that handle article-related concerns — filtering, lookup, and access control — so that route handlers can declare these behaviours declaratively rather than repeating the logic inline [[target/app/api/dependencies/articles.py]].

[`get_articles_filters`](target/app/api/dependencies/articles.py::get_articles_filters) is the simplest of the three: it gathers the query-string parameters used when listing articles and bundles them into a single `ArticlesFilters` object [[target/app/api/dependencies/articles.py::get_articles_filters]]. It accepts optional `tag`, `author`, and `favorited` strings alongside integer `limit` and `offset` values that are validated through FastAPI's `Query` helper, ensuring `limit` is at least 1 and `offset` is at least 0 [[target/app/api/dependencies/articles.py::get_articles_filters]]. Because every parameter carries a default, a caller that supplies none receives a default-paged, unfiltered result [[target/app/api/dependencies/articles.py::get_articles_filters]].

[`get_article_by_slug_from_path`](target/app/api/dependencies/articles.py::get_article_by_slug_from_path) is an asynchronous dependency that resolves a single `Article` from the URL slug [[target/app/api/dependencies/articles.py::get_article_by_slug_from_path]]. It injects three values: the `slug` path parameter (validated to be at least one character), an optionally authenticated `User` via `get_current_user_authorizer(required=False)` so that unauthenticated callers are still permitted, and an `ArticlesRepository` instance for the database lookup [[target/app/api/dependencies/articles.py::get_article_by_slug_from_path]]. Both the slug and the possibly-absent user are forwarded to the repository so that per-user context such as favourite status can be taken into account [[target/app/api/dependencies/articles.py::get_article_by_slug_from_path]]. If the repository raises `EntityDoesNotExist`, the function catches it and re-raises an `HTTPException` with a `404 Not Found` status, translating a database-layer signal into a proper HTTP response [[target/app/api/dependencies/articles.py::get_article_by_slug_from_path]].

[`check_article_modification_permissions`](target/app/api/dependencies/articles.py::check_article_modification_permissions) builds directly on `get_article_by_slug_from_path`: it injects the already-resolved `Article` from that dependency alongside a now-required authenticated `User`, then calls `check_user_can_modify_article` to verify authorship [[target/app/api/dependencies/articles.py::check_article_modification_permissions]]. If the check fails, it raises an `HTTPException` with a `403 Forbidden` status; if it passes, the function returns `None`, making it a pure gate that is used only for its side effect of blocking unauthorised requests [[target/app/api/dependencies/articles.py::check_article_modification_permissions]]. The three functions therefore form a natural layering: the filter dependency feeds listing routes, the slug-lookup dependency feeds any route that targets a specific article, and the permission dependency composes on top of the lookup to guard write operations [[target/app/api/dependencies/articles.py]].

## check_article_modification_permissions

`check_article_modification_permissions` is a FastAPI dependency function that enforces write-access control on an article, returning nothing on success and blocking the request if the current user is not permitted to modify the article [[target/app/api/dependencies/articles.py::check_article_modification_permissions]].

It accepts two injected parameters: `current_article`, an `Article` instance resolved via the `get_article_by_slug_from_path` dependency, and `user`, a `User` instance resolved via `get_current_user_authorizer()` [[target/app/api/dependencies/articles.py::get_article_by_slug_from_path]] [[target/app/api/dependencies/authentication.py::get_current_user_authorizer]]. Both parameters are wired through FastAPI's `Depends` mechanism, meaning the framework resolves and injects them automatically when the function is used as a dependency in a route [[target/app/api/dependencies/articles.py::check_article_modification_permissions]].

The function's sole logic is a permission check: it calls `check_user_can_modify_article` with the resolved article and user, and if that check returns a falsy value it raises an `HTTPException` with HTTP status `403 Forbidden`, signalling that the authenticated user is not the author of the article [[target/app/api/dependencies/articles.py::check_article_modification_permissions]]. The function declares a return type of `None`, so callers that pass the check receive no value — the dependency is used purely for its side effect of gating access [[target/app/api/dependencies/articles.py::check_article_modification_permissions]].

> **Raises:** fastapi.HTTPException

> **FastAPI deps:** get_article_by_slug_from_path, get_current_user_authorizer

## get_article_by_slug_from_path

`get_article_by_slug_from_path` is an asynchronous FastAPI dependency function that retrieves a single article by its URL slug [[target/app/api/dependencies/articles.py::get_article_by_slug_from_path]]. It accepts three injected parameters: `slug`, a path parameter validated to be at least one character long; `user`, an optionally authenticated [`User`](target/app/api/dependencies/articles.py) resolved via `get_current_user_authorizer(required=False)`, meaning unauthenticated callers are permitted [[target/app/api/dependencies/authentication.py::get_current_user_authorizer]]; and `articles_repo`, an [`ArticlesRepository`](target/app/api/dependencies/articles.py) instance injected through `get_repository` [[target/app/api/dependencies/database.py::get_repository]].

The function delegates the lookup to `articles_repo.get_article_by_slug`, passing both the slug and the (possibly absent) requesting user so that per-user context — such as whether the article is favourited — can be factored in [[target/app/api/dependencies/articles.py::get_article_by_slug_from_path]]. If the repository signals that no matching article exists by raising `EntityDoesNotExist`, the function catches that exception and re-raises an `HTTPException` with a `404 Not Found` status code [[target/app/api/dependencies/articles.py::get_article_by_slug_from_path]]. On success it returns the resolved [`Article`](target/app/api/dependencies/articles.py) object [[target/app/api/dependencies/articles.py::get_article_by_slug_from_path]].

> **Raises:** fastapi.HTTPException

> **FastAPI deps:** get_current_user_authorizer, get_repository

## get_articles_filters

`get_articles_filters` is a dependency function that collects query-string filter parameters for listing articles and packages them into a single structured object [[target/app/api/dependencies/articles.py::get_articles_filters]]. It accepts five optional inputs: `tag`, `author`, and `favorited` are plain `Optional[str]` values that default to `None`, while `limit` and `offset` are integers validated through FastAPI's `Query` helper — `limit` must be at least 1 and defaults to `DEFAULT_ARTICLES_LIMIT`, and `offset` must be at least 0 and defaults to `DEFAULT_ARTICLES_OFFSET` [[target/app/api/dependencies/articles.py::get_articles_filters]]. The function constructs and returns an `ArticlesFilters` instance populated with all five values, which becomes the unified filter object consumed by the caller [[target/app/api/dependencies/articles.py::get_articles_filters]]. Because every parameter has a default, no argument is required; a caller that provides none will receive a default-paged, unfiltered result set [[target/app/api/dependencies/articles.py]]. The use of `Query` on `limit` and `offset` signals that this function is designed to be injected as a FastAPI dependency, so the framework will parse and validate those fields directly from the HTTP query string before the function is invoked [[target/app/api/dependencies/articles.py::get_articles_filters]].
