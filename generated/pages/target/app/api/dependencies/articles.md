# articles

This module is a collection of FastAPI dependency functions that handle article-related concerns — filtering, lookup, and authorization — for use across route handlers [[target/app/api/dependencies/articles.py]].

`get_articles_filters` collects query-string parameters for article listing and packages them into a single typed `ArticlesFilters` object [[target/app/api/dependencies/articles.py::get_articles_filters]]. It accepts three optional string filters (`tag`, `author`, and `favorited`) alongside paginated `limit` and `offset` integers, both of which are validated by FastAPI's `Query` helper before the function body is reached [[target/app/api/dependencies/articles.py::get_articles_filters]]. Route handlers that need to filter a list of articles declare this function as a dependency and receive the assembled object directly [[target/app/api/dependencies/articles.py::get_articles_filters]].

`get_article_by_slug_from_path` is an asynchronous dependency that resolves a URL slug into a concrete `Article` object [[target/app/api/dependencies/articles.py::get_article_by_slug_from_path]]. It reads the slug from the request path, accepts an optional authenticated user so that unauthenticated callers are not blocked, and receives an `ArticlesRepository` instance through dependency injection to perform the database lookup [[target/app/api/dependencies/articles.py::get_article_by_slug_from_path]]. The optional user is forwarded to the repository so that per-user state such as favouriting can be reflected in the returned article [[target/app/api/dependencies/articles.py::get_article_by_slug_from_path]]. If the repository raises `EntityDoesNotExist`, the function catches it and re-raises an `HTTPException` with a `404 Not Found` status code, turning a database-level signal into a proper HTTP response [[target/app/api/dependencies/articles.py::get_article_by_slug_from_path]].

`check_article_modification_permissions` builds on top of `get_article_by_slug_from_path` to enforce write-access control [[target/app/api/dependencies/articles.py::check_article_modification_permissions]]. It declares both `get_article_by_slug_from_path` and a required authenticated user as its own injected dependencies, so FastAPI resolves the article and the current user before the guard runs [[target/app/api/dependencies/articles.py::check_article_modification_permissions]]. If the resolved user is not the author of the article, the function raises an `HTTPException` with HTTP status 403 Forbidden; otherwise it returns `None` and the route proceeds [[target/app/api/dependencies/articles.py::check_article_modification_permissions]]. Any route that lists this function as a dependency is therefore protected against modification attempts by non-authors without needing to repeat that logic inline [[target/app/api/dependencies/articles.py::check_article_modification_permissions]].

## check_article_modification_permissions

`check_article_modification_permissions` [[target/app/api/dependencies/articles.py::check_article_modification_permissions]] is a FastAPI dependency function that enforces write-access control on an article. It accepts two injected parameters: `current_article`, resolved via `get_article_by_slug_from_path` [[target/app/api/dependencies/articles.py::get_article_by_slug_from_path]], and `user`, resolved via `get_current_user_authorizer()` [[target/app/api/dependencies/authentication.py::get_current_user_authorizer]]. Both parameters are wired through FastAPI's `Depends` mechanism, meaning the framework resolves them automatically before invoking the function [[target/app/api/dependencies/articles.py::check_article_modification_permissions]]. The function returns `None` on success — its sole job is to act as a guard [[target/app/api/dependencies/articles.py::check_article_modification_permissions]]. Internally it calls `check_user_can_modify_article` with the resolved article and user; if that check returns a falsy value, the function raises an `HTTPException` with HTTP status 403 Forbidden [[target/app/api/dependencies/articles.py::check_article_modification_permissions]]. Any route that declares this function as a dependency will therefore be blocked with a 403 response whenever the authenticated user is not the author of the targeted article [[target/app/api/dependencies/articles.py::check_article_modification_permissions]].

> **Raises:** fastapi.HTTPException

> **FastAPI deps:** get_article_by_slug_from_path, get_current_user_authorizer

## get_article_by_slug_from_path

`get_article_by_slug_from_path` is an asynchronous FastAPI dependency function that retrieves a single article by its URL slug [[target/app/api/dependencies/articles.py::get_article_by_slug_from_path]]. It accepts three injected parameters: a `slug` string drawn from the request path (enforced to be at least one character long), an optional `User` resolved via `get_current_user_authorizer(required=False)` so that unauthenticated callers are permitted [[target/app/api/dependencies/authentication.py::get_current_user_authorizer]], and an `ArticlesRepository` instance supplied by `get_repository(ArticlesRepository)` [[target/app/api/dependencies/database.py::get_repository]]. At runtime the function delegates to `articles_repo.get_article_by_slug`, passing both the slug and the (possibly absent) requesting user so that per-user state such as favouriting can be reflected in the result [[target/app/api/dependencies/articles.py::get_article_by_slug_from_path]]. If the repository signals that no matching article exists by raising `EntityDoesNotExist`, the function catches that exception and re-raises an `HTTPException` with a `404 Not Found` status code [[target/app/api/dependencies/articles.py::get_article_by_slug_from_path]]. On success it returns the resolved `Article` object to whichever route handler declared this function as a dependency [[target/app/api/dependencies/articles.py::get_article_by_slug_from_path]].

> **Raises:** fastapi.HTTPException

> **FastAPI deps:** get_current_user_authorizer, get_repository

## get_articles_filters

`get_articles_filters` is a dependency function that collects query-string filter parameters for article listing and packages them into a single typed object [[target/app/api/dependencies/articles.py::get_articles_filters]]. It accepts five optional inputs: `tag`, `author`, and `favorited` are plain `Optional[str]` values that default to `None`, while `limit` and `offset` are integers validated through FastAPI's `Query` helper — `limit` must be at least 1 and defaults to `DEFAULT_ARTICLES_LIMIT`, and `offset` must be at least 0 and defaults to `DEFAULT_ARTICLES_OFFSET` [[target/app/api/dependencies/articles.py::get_articles_filters]]. The function constructs and returns an `ArticlesFilters` instance populated with all five values, making the assembled filter object available for injection into route handlers that need it [[target/app/api/dependencies/articles.py::get_articles_filters]]. No exceptions are raised explicitly; constraint violations on `limit` or `offset` (such as a value below the declared minimum) are handled automatically by FastAPI's query validation before the function body is reached [[target/app/api/dependencies/articles.py]].
