# database

This module provides the full chain of FastAPI dependency functions needed to inject a typed database repository into any route handler [[target/app/api/dependencies/database.py]].

The chain begins with `_get_db_pool`, which reads the application-level asyncpg connection pool from `request.app.state.pool` and returns it as a `Pool` instance [[target/app/api/dependencies/database.py::_get_db_pool]]. The pool is expected to have been attached to the application's state before the first request arrives, so this function itself does no setup and raises no exceptions [[target/app/api/dependencies/database.py::_get_db_pool]].

The next link is `_get_connection_from_pool`, an asynchronous generator that depends on `_get_db_pool` and acquires a single `Connection` from the pool via `pool.acquire()` inside an `async with` block [[target/app/api/dependencies/database.py::_get_connection_from_pool]]. It yields that connection to the caller and, because the acquisition is managed by an async context manager, automatically releases it back to the pool once the request scope exits [[target/app/api/dependencies/database.py::_get_connection_from_pool]].

The outermost piece is `get_repository`, a factory function that closes over a caller-supplied repository class (`repo_type: Type[BaseRepository]`) and returns a new FastAPI-compatible dependency function [[target/app/api/dependencies/database.py::get_repository]]. That inner function, `_get_repo`, depends on `_get_connection_from_pool` and instantiates the repository by calling `repo_type(conn)`, wiring the live connection directly into the chosen class [[target/app/api/dependencies/database.py::get_repository]]. Because each call to `get_repository` with a different class produces an independent resolver, route handlers can declare their specific repository type with a single `Depends(get_repository(SomeRepository))` expression, and the full pool → connection → repository chain is satisfied automatically [[target/app/api/dependencies/database.py::get_repository]] [[target/app/api/dependencies/database.py]].

## _get_connection_from_pool

`_get_connection_from_pool` is an asynchronous generator function defined in [`target/app/api/dependencies/database.py`](target/app/api/dependencies/database.py) that yields a single database connection for use within a request [[target/app/api/dependencies/database.py::_get_connection_from_pool]]. It accepts one parameter, `pool`, a `Pool` instance that is resolved automatically via FastAPI's dependency injection using `_get_db_pool` as its source [[target/app/api/dependencies/database.py::_get_connection_from_pool]] [[target/app/api/dependencies/database.py::_get_db_pool]]. The function acquires a connection from that pool using `pool.acquire()` inside an `async with` block, then yields the resulting `Connection` object to the caller [[target/app/api/dependencies/database.py::_get_connection_from_pool]]. Its return type is `AsyncGenerator[Connection, None]`, meaning it produces exactly one `Connection` and returns nothing after the generator is exhausted [[target/app/api/dependencies/database.py::_get_connection_from_pool]]. Because `pool.acquire()` is used as an async context manager, the connection is automatically released back to the pool once the caller's scope exits, making this a safe and self-contained way to borrow a connection for the lifetime of a single request [[target/app/api/dependencies/database.py::_get_connection_from_pool]].

> **FastAPI deps:** _get_db_pool

## _get_db_pool

`_get_db_pool` is a simple dependency helper that accepts a single [`request: Request`](target/app/api/dependencies/database.py::_get_db_pool) parameter and returns the application-level database connection pool [[target/app/api/dependencies/database.py::_get_db_pool]]. It retrieves the pool by reading `request.app.state.pool`, meaning the pool is expected to have been attached to the application's state object before any request is handled [[target/app/api/dependencies/database.py::_get_db_pool]]. The return type is declared as `Pool` [[target/app/api/dependencies/database.py::_get_db_pool]]. This function carries no decorators of its own and raises no exceptions directly; it is intended to be used as a FastAPI dependency that other route handlers or dependencies can declare to gain access to the shared pool [[target/app/api/dependencies/database.py]].

## get_repository

`get_repository` is a factory function that, given a repository class, returns a FastAPI-compatible dependency function bound to that class [[target/app/api/dependencies/database.py::get_repository]]. It accepts a single parameter, `repo_type`, typed as `Type[BaseRepository]`, which specifies which repository class should be instantiated [[target/app/api/dependencies/database.py::get_repository]]. Its return type is `Callable[[Connection], BaseRepository]`, meaning it produces a callable that takes a database connection and yields a repository instance [[target/app/api/dependencies/database.py::get_repository]].

The inner function `_get_repo` uses FastAPI's `Depends` to receive a `Connection` from the connection pool, then constructs and returns an instance by calling `repo_type(conn)` [[target/app/api/dependencies/database.py::get_repository]]. Because the outer function closes over `repo_type`, each call to `get_repository` with a different class produces an independent, correctly-typed dependency resolver [[target/app/api/dependencies/database.py::get_repository]]. The file itself houses this pattern as the primary mechanism for injecting database-backed repositories into route handlers [[target/app/api/dependencies/database.py]].
