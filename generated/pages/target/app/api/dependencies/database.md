# database

This module is the database dependency layer for the FastAPI application, providing the three-step chain that connects an incoming HTTP request to a fully constructed repository object ready for use in a route handler [[target/app/api/dependencies/database.py]].

The chain begins with `_get_db_pool`, a minimal accessor that receives FastAPI's `Request` object and returns the shared `Pool` instance that was attached to `request.app.state` when the application started [[target/app/api/dependencies/database.py::_get_db_pool]]. It contains no logic beyond reading and returning that reference, making it a pure extraction point for the application-level pool [[target/app/api/dependencies/database.py::_get_db_pool]].

That pool is consumed by `_get_connection_from_pool`, an async generator dependency that borrows one `Connection` from the pool for the lifetime of a single request [[target/app/api/dependencies/database.py::_get_connection_from_pool]]. It declares `pool` as an injected parameter resolved via `Depends(_get_db_pool)`, so FastAPI automatically calls `_get_db_pool` first and passes its result in [[target/app/api/dependencies/database.py::_get_connection_from_pool]] [[target/app/api/dependencies/database.py::_get_db_pool]]. Because the function uses `yield` inside an `async with pool.acquire()` context manager, FastAPI treats it as a dependency with cleanup: the connection is released back to the pool automatically once the request finishes [[target/app/api/dependencies/database.py::_get_connection_from_pool]].

The top of the chain is `get_repository`, a factory function that closes over a specific `BaseRepository` subclass and returns a FastAPI-compatible dependency callable wired to a live connection [[target/app/api/dependencies/database.py::get_repository]]. It accepts `repo_type` typed as `Type[BaseRepository]` and returns a `Callable[[Connection], BaseRepository]`; the inner function `_get_repo` uses `Depends(_get_connection_from_pool)` to obtain its connection, then constructs and returns the requested repository via `repo_type(conn)` [[target/app/api/dependencies/database.py::get_repository]]. This design means route handlers can declare a specific repository as a dependency without knowing anything about how connections are pooled or acquired — all of that wiring is encapsulated here [[target/app/api/dependencies/database.py]] [[target/app/api/dependencies/database.py::get_repository]].

## _get_connection_from_pool

`_get_connection_from_pool` is an asynchronous generator function that borrows a single database connection from a connection pool and makes it available to the caller for the duration of a request [[target/app/api/dependencies/database.py::_get_connection_from_pool]]. It accepts one parameter, `pool`, which is a `Pool` instance injected automatically by FastAPI's dependency injection system via `Depends(_get_db_pool)`, meaning the pool itself is resolved by calling `_get_db_pool` before this function runs [[target/app/api/dependencies/database.py::_get_db_pool]] [[target/app/api/dependencies/database.py::_get_connection_from_pool]]. The function acquires a connection from that pool using `pool.acquire()` as an async context manager, then `yield`s the resulting `Connection` object to the dependent route or function [[target/app/api/dependencies/database.py::_get_connection_from_pool]]. Because it uses `yield`, FastAPI treats it as a dependency with cleanup: once the caller is finished, control returns here and the context manager releases the connection back to the pool automatically [[target/app/api/dependencies/database.py::_get_connection_from_pool]]. Its declared return type is `AsyncGenerator[Connection, None]`, confirming it produces exactly one `Connection` value and no final return value [[target/app/api/dependencies/database.py::_get_connection_from_pool]].

## _get_db_pool

`_get_db_pool` is a small accessor function that takes a single argument — `request`, typed as `Request` — and returns a `Pool` object [[target/app/api/dependencies/database.py::_get_db_pool]]. Its sole job is to extract the shared database connection pool that was attached to the application's state at startup, retrieving it via `request.app.state.pool` [[target/app/api/dependencies/database.py::_get_db_pool]]. The return type is declared as `Pool`, matching the object stored on the application state [[target/app/api/dependencies/database.py::_get_db_pool]]. The function contains no branching, no error handling, and no side effects; it simply reads and returns the pool reference in a single expression [[target/app/api/dependencies/database.py::_get_db_pool]].

## get_repository

`get_repository` is a factory function that, given a repository class, returns a FastAPI-compatible dependency function wired to a live database connection [[target/app/api/dependencies/database.py::get_repository]].

It accepts a single parameter, `repo_type`, typed as `Type[BaseRepository]`, which is the concrete repository class the caller wants to instantiate [[target/app/api/dependencies/database.py::get_repository]]. The function returns a `Callable[[Connection], BaseRepository]`, meaning the value it produces is itself a callable that FastAPI's dependency injection system can invoke [[target/app/api/dependencies/database.py::get_repository]].

The inner function `_get_repo` uses `Depends(_get_connection_from_pool)` to declare that it requires a `Connection` object resolved from the connection pool at request time [[target/app/api/dependencies/database.py::get_repository]]. When FastAPI calls `_get_repo`, it passes that resolved connection into `repo_type(conn)`, constructing and returning the requested repository instance [[target/app/api/dependencies/database.py::get_repository]].

The overall pattern lets route handlers declare a specific repository type as a dependency without knowing how the database connection is obtained — `get_repository` encapsulates that wiring and hands back a ready-to-use dependency callable [[target/app/api/dependencies/database.py]] [[target/app/api/dependencies/database.py::get_repository]].
