# authentication

This module is the central authentication layer for the FastAPI application, responsible for extracting JWT bearer tokens from incoming HTTP requests, validating them, and resolving the authenticated user as a dependency [[target/app/api/dependencies/authentication.py]].

The foundation is [`RWAPIKeyHeader`](target/app/api/dependencies/authentication.py::RWAPIKeyHeader), a custom subclass of FastAPI's `APIKeyHeader` that overrides the async `__call__` method to intercept any `StarletteHTTPException` raised when the `Authorization` header is missing, re-raising it as a project-local `HTTPException` with a standardised authentication-required message [[target/app/api/dependencies/authentication.py::RWAPIKeyHeader]]. This ensures all authentication failures surface with a consistent error shape across the application [[target/app/api/dependencies/authentication.py::RWAPIKeyHeader]].

On top of that, [`_get_authorization_header`](target/app/api/dependencies/authentication.py::_get_authorization_header) uses `RWAPIKeyHeader` as a `Security` dependency to retrieve the raw header string, then splits it into a prefix and a token, raising a `403 Forbidden` exception if the value cannot be split or if the prefix does not match the configured `jwt_token_prefix` [[target/app/api/dependencies/authentication.py::_get_authorization_header]]. Its counterpart, [`_get_authorization_header_optional`](target/app/api/dependencies/authentication.py::_get_authorization_header_optional), wraps the same logic but supplies `auto_error=False` to `RWAPIKeyHeader` so that a missing header returns an empty string rather than an error, making it safe for optional-auth endpoints [[target/app/api/dependencies/authentication.py::_get_authorization_header_optional]]. The factory function [`_get_authorization_header_retriever`](target/app/api/dependencies/authentication.py::_get_authorization_header_retriever) selects between these two callables based on a `required` boolean flag, returning `_get_authorization_header` when authentication is mandatory and `_get_authorization_header_optional` when it is not [[target/app/api/dependencies/authentication.py::_get_authorization_header_retriever]].

With a validated token in hand, [`_get_current_user`](target/app/api/dependencies/authentication.py::_get_current_user) decodes the JWT via `jwt.get_username_from_token`, raising `403 Forbidden` on a malformed payload, and then looks up the identified username in the database through a `UsersRepository`; if no matching record exists an `EntityDoesNotExist` exception is caught and the same `403 Forbidden` response is returned, preventing username enumeration [[target/app/api/dependencies/authentication.py::_get_current_user]]. Its sibling, [`_get_current_user_optional`](target/app/api/dependencies/authentication.py::_get_current_user_optional), delegates to `_get_current_user` when a token is present and returns `None` when no credentials are supplied, yielding an `Optional[User]` return type that covers both authenticated and anonymous callers [[target/app/api/dependencies/authentication.py::_get_current_user_optional]].

The public surface of the module is the factory function [`get_current_user_authorizer`](target/app/api/dependencies/authentication.py::get_current_user_authorizer), which route handlers call with a `required` keyword argument to obtain either `_get_current_user` or `_get_current_user_optional` as their FastAPI dependency, giving each endpoint a single, declarative way to express whether an unauthenticated request should be rejected or tolerated [[target/app/api/dependencies/authentication.py::get_current_user_authorizer]].

## RWAPIKeyHeader

`RWAPIKeyHeader` is a class defined in [`target/app/api/dependencies/authentication.py`](target/app/api/dependencies/authentication.py) that extends FastAPI's `APIKeyHeader` base class, making it a custom security dependency within the application [[target/app/api/dependencies/authentication.py::RWAPIKeyHeader]]. It is not a Pydantic model; it inherits from the external `fastapi.security.APIKeyHeader` and carries no additional fields of its own [[target/app/api/dependencies/authentication.py::RWAPIKeyHeader]].

Its sole method is [`__call__`](target/app/api/dependencies/authentication.py::RWAPIKeyHeader::__call__), an asynchronous method that serves as the entry point when FastAPI's dependency injection system invokes this dependency [[target/app/api/dependencies/authentication.py::RWAPIKeyHeader::__call__]]. The method accepts a `requests.Request` object and returns an `Optional[str]` representing the extracted API key value if one is present [[target/app/api/dependencies/authentication.py::RWAPIKeyHeader::__call__]]. Its core logic delegates to the parent class by calling `await super().__call__(request)`, relying on Starlette's built-in API key header extraction behaviour [[target/app/api/dependencies/authentication.py::RWAPIKeyHeader::__call__]]. When no valid API key header is found, the parent raises a `StarletteHTTPException`; `RWAPIKeyHeader` catches that exception and re-raises a project-local `HTTPException` with a standardised authentication-required detail message, ensuring authentication failures surface with a consistent error shape aligned with the application's own exception handling conventions [[target/app/api/dependencies/authentication.py::RWAPIKeyHeader::__call__]] [[target/app/api/dependencies/authentication.py::RWAPIKeyHeader]]. The `# noqa: WPS610` comment on the method signature suppresses a linter warning, following an established pattern in this codebase for FastAPI dependency injection methods [[target/app/api/dependencies/authentication.py::RWAPIKeyHeader::__call__]].

### __call__

The `__call__` method is an asynchronous method defined on the `RWAPIKeyHeader` class that acts as the entry point when the dependency is invoked by FastAPI's dependency injection system [[target/app/api/dependencies/authentication.py::RWAPIKeyHeader::__call__]]. It accepts a `requests.Request` object as its sole non-self parameter and returns an `Optional[str]`, representing the extracted API key value if one is present [[target/app/api/dependencies/authentication.py::RWAPIKeyHeader::__call__]].

Its core logic delegates to the parent class implementation by calling `super().__call__(request)` with `await`, relying on Starlette's built-in API key header extraction behaviour [[target/app/api/dependencies/authentication.py::RWAPIKeyHeader::__call__]]. If the parent raises a `StarletteHTTPException` — which would occur when no valid API key header is found — the method catches it and re-raises a project-local `HTTPException`, substituting in a standardised authentication-required detail message rather than propagating the raw Starlette exception [[target/app/api/dependencies/authentication.py::RWAPIKeyHeader::__call__]]. This wrapping ensures that authentication failures surface with a consistent error shape aligned with the application's own exception handling conventions [[target/app/api/dependencies/authentication.py::RWAPIKeyHeader]]. The `# noqa: WPS610` comment suppresses a linter warning, which is an established pattern in this codebase for FastAPI dependency injection methods [[target/app/api/dependencies/authentication.py::RWAPIKeyHeader::__call__]].

> **Raises:** starlette.exceptions.HTTPException

## _get_authorization_header

`_get_authorization_header` is a FastAPI dependency function that extracts and validates a Bearer token from an incoming HTTP request's authorization header [[target/app/api/dependencies/authentication.py::_get_authorization_header]]. It accepts two injected parameters: `api_key`, a raw header string retrieved via `Security(RWAPIKeyHeader(...))`, and `settings`, the application configuration object supplied by `Depends(get_app_settings)` [[target/app/api/dependencies/authentication.py::_get_authorization_header]] [[target/app/core/config.py::get_app_settings]].

The function attempts to split `api_key` on a single space into a prefix and a token [[target/app/api/dependencies/authentication.py::_get_authorization_header]]. If the split does not yield exactly two parts — because no space is present or there are too many — a `ValueError` is caught and an `HTTPException` with status `403 Forbidden` is raised immediately [[target/app/api/dependencies/authentication.py::_get_authorization_header]]. Even when the split succeeds, the extracted prefix is compared against `settings.jwt_token_prefix`; if they do not match, a second `403 Forbidden` `HTTPException` is raised with the same wrong-prefix detail message [[target/app/api/dependencies/authentication.py::_get_authorization_header]] [[target/app/core/config.py::get_app_settings]].

When both checks pass, the function returns the token portion of the header as a plain `str`, ready for downstream authentication logic [[target/app/api/dependencies/authentication.py::_get_authorization_header]].

> **Raises:** starlette.exceptions.HTTPException

> **FastAPI deps:** get_app_settings

## _get_authorization_header_optional

`_get_authorization_header_optional` is a FastAPI dependency function that optionally extracts and validates an authorization header from an incoming request [[target/app/api/dependencies/authentication.py::_get_authorization_header_optional]]. It accepts two injected parameters: `authorization`, an optional string pulled from the request via `Security(RWAPIKeyHeader(name=HEADER_KEY, auto_error=False))` which suppresses automatic errors when the header is absent, and `settings`, an `AppSettings` instance supplied by the `get_app_settings` dependency [[target/app/api/dependencies/authentication.py::_get_authorization_header_optional]] [[target/app/core/config.py::get_app_settings]]. When the `authorization` header is present, the function delegates to `_get_authorization_header`, passing both the raw header value and the application settings, and returns whatever that call produces [[target/app/api/dependencies/authentication.py::_get_authorization_header_optional]]. When no header is provided, the function returns an empty string rather than raising an error, making it suitable for endpoints where authentication is optional [[target/app/api/dependencies/authentication.py::_get_authorization_header_optional]]. In both cases the declared return type is `str` [[target/app/api/dependencies/authentication.py::_get_authorization_header_optional]].

> **FastAPI deps:** get_app_settings

## _get_authorization_header_retriever

`_get_authorization_header_retriever` is a factory function that selects and returns one of two authorization-header retrieval callables based on whether the header is required [[target/app/api/dependencies/authentication.py::_get_authorization_header_retriever]]. It accepts a single keyword-only argument, `required`, which defaults to `True` [[target/app/api/dependencies/authentication.py::_get_authorization_header_retriever]]. When `required` is `True` it returns `_get_authorization_header`, and when `False` it returns `_get_authorization_header_optional` [[target/app/api/dependencies/authentication.py::_get_authorization_header_retriever]]. The return type is annotated as `Callable`, suppressing the missing type-parameter warning with a `# type: ignore` comment [[target/app/api/dependencies/authentication.py::_get_authorization_header_retriever]].

## _get_current_user

`_get_current_user` is an async dependency function that resolves the currently authenticated user from a JWT token, returning a [`User`](target/app/api/dependencies/authentication.py) object [[target/app/api/dependencies/authentication.py::_get_current_user]].

It accepts three injected parameters via FastAPI's `Depends` mechanism [[target/app/api/dependencies/authentication.py::_get_current_user]]. The `users_repo` parameter is a `UsersRepository` instance supplied by `get_repository` [[target/app/api/dependencies/database.py::get_repository]]. The `token` string is extracted from the incoming request's authorization header by `_get_authorization_header_retriever` [[target/app/api/dependencies/authentication.py::_get_authorization_header_retriever]]. The `settings` parameter carries application configuration, including the secret key used to verify the token, and is provided by `get_app_settings` [[target/app/core/config.py::get_app_settings]].

The function first attempts to decode the JWT by calling `jwt.get_username_from_token`, passing the token and the application secret key obtained via `settings.secret_key.get_secret_value()` [[target/app/api/dependencies/authentication.py::_get_current_user]]. If the token is malformed or the decode fails with a `ValueError`, the function raises an `HTTPException` with a `403 Forbidden` status and a malformed-payload detail message [[target/app/api/dependencies/authentication.py::_get_current_user]].

If decoding succeeds, the function awaits `users_repo.get_user_by_username` to look up the user identified by the decoded username [[target/app/api/dependencies/authentication.py::_get_current_user]]. If no matching user exists and an `EntityDoesNotExist` exception is raised by the repository, the function again raises an `HTTPException` with `403 Forbidden` and the same malformed-payload detail, preventing username enumeration [[target/app/api/dependencies/authentication.py::_get_current_user]]. On success, the resolved `User` object is returned directly to the caller [[target/app/api/dependencies/authentication.py::_get_current_user]].

> **Raises:** starlette.exceptions.HTTPException

> **FastAPI deps:** _get_authorization_header_retriever, get_repository, get_app_settings

## _get_current_user_optional

`_get_current_user_optional` is an async dependency function that attempts to resolve the currently authenticated user, but treats authentication as optional and returns `None` when no credentials are present [[target/app/api/dependencies/authentication.py::_get_current_user_optional]].

It accepts three injected parameters via FastAPI's `Depends` mechanism [[target/app/api/dependencies/authentication.py::_get_current_user_optional]]. The first is a `UsersRepository` instance, supplied by `get_repository` [[target/app/api/dependencies/database.py::get_repository]]. The second is an optional bearer token string, retrieved by `_get_authorization_header_retriever` called with `required=False`, meaning no error is raised when the `Authorization` header is absent [[target/app/api/dependencies/authentication.py::_get_authorization_header_retriever]]. The third is an `AppSettings` instance provided by `get_app_settings` [[target/app/core/config.py::get_app_settings]].

At runtime, if a token is present the function delegates to the internal `_get_current_user` helper, passing the repository, token, and settings, and returns the resolved `User` object [[target/app/api/dependencies/authentication.py::_get_current_user_optional]]. If the token is absent or falsy, the function returns `None` without attempting any lookup [[target/app/api/dependencies/authentication.py::_get_current_user_optional]]. The return type is therefore `Optional[User]`, reflecting both possible outcomes [[target/app/api/dependencies/authentication.py::_get_current_user_optional]].

> **FastAPI deps:** _get_authorization_header_retriever, get_repository, get_app_settings

## get_current_user_authorizer

`get_current_user_authorizer` is a factory function that selects and returns the appropriate authentication dependency based on whether authentication is required [[target/app/api/dependencies/authentication.py::get_current_user_authorizer]]. It accepts a single keyword-only boolean parameter `required` (defaulting to `True`) and returns a `Callable` [[target/app/api/dependencies/authentication.py::get_current_user_authorizer]]. When `required` is `True`, it returns the strict authenticator (`_get_current_user`); when `False`, it returns the optional variant (`_get_current_user_optional`), allowing routes to declare whether an unauthenticated request should be rejected or tolerated [[target/app/api/dependencies/authentication.py::get_current_user_authorizer]]. The return type is annotated as `Callable` with a `# type: ignore` comment, indicating the precise callable signature is intentionally left unspecified to satisfy FastAPI's dependency injection system [[target/app/api/dependencies/authentication.py::get_current_user_authorizer]].
