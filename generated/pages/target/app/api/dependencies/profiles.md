# profiles

This module serves as a FastAPI dependency provider for profile-related operations, exposing a single injectable function that resolves a user profile from the current request context [[target/app/api/dependencies/profiles.py]].

The function [`get_profile_by_username_from_path`](target/app/api/dependencies/profiles.py::get_profile_by_username_from_path) reads the `username` segment directly from the URL path (enforcing a minimum length of 1) and delegates to `profiles_repo.get_profile_by_username` to retrieve the corresponding [`Profile`](target/app/api/dependencies/profiles.py), passing along the optionally authenticated caller so that follow/unfollow state can be resolved [[target/app/api/dependencies/profiles.py::get_profile_by_username_from_path]]. Authentication is intentionally optional: the current user is obtained via `get_current_user_authorizer(required=False)`, which means the endpoint remains accessible to unauthenticated callers while still enriching the response with relationship state when a valid user is present [[target/app/api/dependencies/profiles.py::get_profile_by_username_from_path]]. The `ProfilesRepository` itself is injected by `get_repository`, which binds the repository to the active database session for the duration of the request [[target/app/api/dependencies/profiles.py::get_profile_by_username_from_path]]. When the requested username cannot be found, the function catches `EntityDoesNotExist` and converts it into an `HTTPException` carrying HTTP 404, keeping the API error contract clean and consistent [[target/app/api/dependencies/profiles.py::get_profile_by_username_from_path]].

## get_profile_by_username_from_path

Fetches a [`Profile`](target/app/api/dependencies/profiles.py) for the `username` extracted from the URL path (minimum length 1), passing the optionally authenticated `user` as the requesting context to `profiles_repo.get_profile_by_username` so that follow/unfollow state can be resolved [[target/app/api/dependencies/profiles.py::get_profile_by_username_from_path]]. The current user is resolved via [`get_current_user_authorizer`](target/app/api/dependencies/authentication.py::get_current_user_authorizer) with `required=False`, meaning the endpoint is accessible without authentication [[target/app/api/dependencies/authentication.py::get_current_user_authorizer]]. The `profiles_repo` dependency is injected by [`get_repository`](target/app/api/dependencies/database.py::get_repository), which supplies a `ProfilesRepository` bound to the active database session [[target/app/api/dependencies/database.py::get_repository]]. If the requested username does not exist, `EntityDoesNotExist` is caught and re-raised as an `HTTPException` with status 404 [[target/app/api/dependencies/profiles.py::get_profile_by_username_from_path]].

> **Raises:** fastapi.HTTPException

> **FastAPI deps:** get_current_user_authorizer, get_repository
