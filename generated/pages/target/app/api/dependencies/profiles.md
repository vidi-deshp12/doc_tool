# profiles

This module serves as a FastAPI dependency provider for profile-related route parameters, exposing a single async dependency function that resolves a user profile from the URL path [[target/app/api/dependencies/profiles.py]].

The sole export is `get_profile_by_username_from_path`, an asynchronous dependency function responsible for looking up a user profile by username and returning it to any route that declares it as a dependency [[target/app/api/dependencies/profiles.py::get_profile_by_username_from_path]]. It accepts three injected values: a `username` string extracted directly from the URL path and validated to be at least one character long, an optional `User` representing the authenticated caller (which may be `None` when no credentials are provided, since authentication is permitted but not required), and a `ProfilesRepository` instance used to query the data store [[target/app/api/dependencies/profiles.py::get_profile_by_username_from_path]]. The actual database lookup is delegated to `profiles_repo.get_profile_by_username`, which receives both the target username and the requesting user so that viewer-relative data such as follow relationships can be resolved [[target/app/api/dependencies/profiles.py::get_profile_by_username_from_path]]. When the lookup succeeds, the function returns a `Profile` object directly to the calling route [[target/app/api/dependencies/profiles.py::get_profile_by_username_from_path]]. If no matching user exists and the repository raises an `EntityDoesNotExist` exception, the function catches it and re-raises it as an `HTTPException` with a `404 Not Found` status code, translating a data-layer error into a proper HTTP response [[target/app/api/dependencies/profiles.py::get_profile_by_username_from_path]].

## get_profile_by_username_from_path

`get_profile_by_username_from_path` is an asynchronous FastAPI dependency function that looks up a user profile by username and returns it to the caller [[target/app/api/dependencies/profiles.py::get_profile_by_username_from_path]].

It accepts three injected parameters: a `username` string extracted from the URL path (enforced to be at least one character long via `Path`), an optional `User` object representing the currently authenticated caller (which may be `None` when no credentials are supplied), and a `ProfilesRepository` instance used to query the data store [[target/app/api/dependencies/profiles.py::get_profile_by_username_from_path]]. The optional current user is resolved through `get_current_user_authorizer` called with `required=False`, meaning authentication is permitted but not mandatory [[target/app/api/dependencies/authentication.py::get_current_user_authorizer]]. The repository is provided via `get_repository`, which handles database session injection [[target/app/api/dependencies/database.py::get_repository]].

The function delegates the actual database lookup to `profiles_repo.get_profile_by_username`, passing both the target `username` and the `requested_user` so that the repository can resolve follow relationships or other viewer-relative data [[target/app/api/dependencies/profiles.py::get_profile_by_username_from_path]]. On success it returns a `Profile` object [[target/app/api/dependencies/profiles.py::get_profile_by_username_from_path]]. If the repository raises an `EntityDoesNotExist` exception because no matching user is found, the function catches it and raises an `HTTPException` with a `404 Not Found` status code instead [[target/app/api/dependencies/profiles.py::get_profile_by_username_from_path]].

> **Raises:** fastapi.HTTPException

> **FastAPI deps:** get_current_user_authorizer, get_repository
