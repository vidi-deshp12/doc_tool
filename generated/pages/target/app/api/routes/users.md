# users

This module is the API route handler for user-account operations, defining the FastAPI `router` and the two endpoint functions that serve the authenticated user resource [[target/app/api/routes/users.py]].

`retrieve_current_user` handles the `GET /api/user` endpoint and returns the currently authenticated user's profile [[target/app/api/routes/users.py::retrieve_current_user]]. The authenticated `User` object is resolved through FastAPI dependency injection via `get_current_user_authorizer`, and application settings are resolved via `get_app_settings` [[target/app/api/routes/users.py::retrieve_current_user]]. Using those inputs, the function mints a fresh JWT access token by calling `jwt.create_access_token_for_user` with the user and the secret key extracted from settings, then assembles the user's `username`, `email`, `bio`, and `image` together with the new token into a `UserWithToken`, which is returned wrapped in a `UserInResponse` [[target/app/api/routes/users.py::retrieve_current_user]].

`update_current_user` handles the `PUT /api/user` endpoint and applies profile changes to the same authenticated user [[target/app/api/routes/users.py::update_current_user]]. It accepts a `UserInUpdate` payload embedded under the `"user"` key in the request body, resolves the current user, a `UsersRepository` instance, and application settings through dependency injection [[target/app/api/routes/users.py::update_current_user]]. Before persisting anything, it enforces uniqueness constraints: if the incoming update contains a new username that differs from the existing one, it checks availability and raises an `HTTPException` with HTTP 400 if the username is already taken; it performs the same check for a changed email address [[target/app/api/routes/users.py::update_current_user]]. Once both checks pass, it writes the changes by calling `users_repo.update_user` with the current user and the flattened update fields [[target/app/api/routes/users.py::update_current_user]]. A fresh JWT is then minted for the updated user using the application's secret key, and the function returns a `UserInResponse` wrapping a `UserWithToken` that bundles the updated profile with the new token [[target/app/api/routes/users.py::update_current_user]].

The two functions share the same response shape — a `UserInResponse` containing a `UserWithToken` — and the same pattern of re-issuing a JWT on every successful request, ensuring the caller always receives a current token whether they are reading or updating their profile [[target/app/api/routes/users.py::retrieve_current_user]] [[target/app/api/routes/users.py::update_current_user]].

## retrieve_current_user

Handles the `GET /api/user` endpoint, returning the authenticated user's profile wrapped in a fresh JWT [[route:GET /api/user]] [[target/app/api/routes/users.py::retrieve_current_user]]. The authenticated `User` is resolved via FastAPI dependency injection using `get_current_user_authorizer`, and application settings are resolved via `get_app_settings` [[target/app/api/dependencies/authentication.py::get_current_user_authorizer]] [[target/app/core/config.py::get_app_settings]]. A new access token is minted by calling `jwt.create_access_token_for_user` with the user and the unwrapped secret key from settings [[target/app/api/routes/users.py::retrieve_current_user]]. The token along with the user's `username`, `email`, `bio`, and `image` are assembled into a `UserWithToken` and returned inside a `UserInResponse` [[target/app/models/schemas/users.py::UserInResponse]] [[target/app/api/routes/users.py::retrieve_current_user]].

> **FastAPI deps:** get_current_user_authorizer, get_app_settings

## update_current_user

Handles `PUT /api/user` to apply profile changes to the currently authenticated user [[route:PUT /api/user]] [[target/app/api/routes/users.py::update_current_user]]. The request body is a [`UserInUpdate`](target/app/models/schemas/users.py::UserInUpdate) object embedded under the `"user"` key [[target/app/models/schemas/users.py::UserInUpdate]]. The authenticated user is resolved via [`get_current_user_authorizer()`](target/app/api/dependencies/authentication.py::get_current_user_authorizer) [[target/app/api/dependencies/authentication.py::get_current_user_authorizer]], the user repository via [`get_repository`](target/app/api/dependencies/database.py::get_repository) [[target/app/api/dependencies/database.py::get_repository]], and application settings via [`get_app_settings`](target/app/core/config.py::get_app_settings) [[target/app/core/config.py::get_app_settings]]. If the update carries a new username that differs from the current one, it checks availability and raises `HTTPException` with HTTP 400 if the username is already taken [[target/app/api/routes/users.py::update_current_user]]. Likewise, if the update carries a new email that differs from the current one, it raises `HTTPException` with HTTP 400 if that email is already in use [[target/app/api/routes/users.py::update_current_user]]. After the uniqueness checks pass, it persists the changes by calling `users_repo.update_user` with the current user and the flattened update fields [[target/app/api/routes/users.py::update_current_user]]. It then mints a fresh JWT access token for the updated user using the application's secret key [[target/app/api/routes/users.py::update_current_user]] [[target/app/core/config.py::get_app_settings]]. The response is a [`UserInResponse`](target/app/models/schemas/users.py::UserInResponse) wrapping a `UserWithToken` that bundles the updated profile fields together with the new token [[target/app/models/schemas/users.py::UserInResponse]] [[target/app/api/routes/users.py::update_current_user]].

> **Raises:** fastapi.HTTPException

> **FastAPI deps:** get_current_user_authorizer, get_repository, get_app_settings
