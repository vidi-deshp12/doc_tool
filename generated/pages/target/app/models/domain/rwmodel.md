# rwmodel

This module is a small but central piece of the domain model layer, providing a shared base class and two formatting utilities that together enforce consistent serialisation conventions across the application [[target/app/models/domain/rwmodel.py]].

`convert_field_to_camel_case` is a pure utility function that accepts a snake\_case `str` and returns its camelCase equivalent by splitting on underscores, leaving the first word unchanged, and capitalising the first letter of every subsequent word — so `my_field_name` becomes `myFieldName` [[target/app/models/domain/rwmodel.py::convert_field_to_camel_case]]. It has no decorators, raises no exceptions, and depends only on Python's built-in string methods [[target/app/models/domain/rwmodel.py]].

`convert_datetime_to_realworld` accepts a `datetime.datetime` and returns a `str` formatted according to the Realworld API convention, where the UTC offset is expressed as a trailing `Z` rather than `+00:00` [[target/app/models/domain/rwmodel.py::convert_datetime_to_realworld]]. It does this in a single chained expression: it attaches an explicit UTC timezone via `replace(tzinfo=datetime.timezone.utc)`, converts to an ISO 8601 string with `.isoformat()`, and then swaps the `+00:00` suffix for `Z` [[target/app/models/domain/rwmodel.py::convert_datetime_to_realworld]]. Like the camel-case helper, it raises no exceptions of its own and relies solely on the standard-library `datetime` module [[target/app/models/domain/rwmodel.py]].

`RWModel` is a Pydantic `BaseModel` subclass that acts as the shared base for all domain models in the codebase, defining no fields of its own [[target/app/models/domain/rwmodel.py::RWModel]]. Its inner `Config` class wires the two helper functions directly into Pydantic's machinery: `convert_field_to_camel_case` is registered as the `alias_generator`, so every snake\_case field name on any subclass is automatically exposed under its camelCase alias, and `convert_datetime_to_realworld` is registered in `json_encoders` so that `datetime.datetime` values are always serialised to the `Z`-suffixed ISO format [[target/app/models/domain/rwmodel.py::RWModel]]. The `Config` also sets `allow_population_by_field_name = True`, meaning subclass instances can be constructed using either the original Python field name or the generated camelCase alias [[target/app/models/domain/rwmodel.py::RWModel]]. Because the alias generator runs automatically for every field, any subclass that needs a *different* alias must declare it explicitly to override the generated one [[target/app/models/domain/rwmodel.py::RWModel]].

## RWModel

`RWModel` is a Pydantic model that serves as the shared base class for domain models in this codebase, inheriting directly from Pydantic's `BaseModel` [[target/app/models/domain/rwmodel.py::RWModel]]. It defines an inner `Config` class that configures three behaviours for all subclasses: population by field name is permitted alongside alias-based population (`allow_population_by_field_name = True`), `datetime.datetime` values are serialised using a `convert_datetime_to_realworld` encoder, and field aliases are automatically generated by passing each field name through `convert_field_to_camel_case` [[target/app/models/domain/rwmodel.py::RWModel]]. Because the alias generator converts snake\_case field names to camelCase automatically, any subclass that needs a *different* alias must declare it explicitly to override the generated one [[target/app/models/domain/rwmodel.py::RWModel]]. `RWModel` declares no fields of its own; its sole purpose is to centralise these serialisation and aliasing conventions so that every domain model that extends it inherits consistent JSON behaviour [[target/app/models/domain/rwmodel.py]].

## convert_datetime_to_realworld

`convert_datetime_to_realworld` takes a single argument `dt` of type `datetime.datetime` and returns a `str` [[target/app/models/domain/rwmodel.py::convert_datetime_to_realworld]]. Its purpose is to format a naive or already-UTC datetime into the ISO 8601 string representation that the Realworld API convention expects, where the UTC offset is expressed as a trailing `Z` rather than `+00:00` [[target/app/models/domain/rwmodel.py::convert_datetime_to_realworld]]. It does this in one chained expression: it first stamps the datetime with an explicit UTC timezone via `dt.replace(tzinfo=datetime.timezone.utc)`, then calls `.isoformat()` to produce the standard ISO string, and finally calls `.replace("+00:00", "Z")` to swap the offset suffix into the compact `Z` form [[target/app/models/domain/rwmodel.py::convert_datetime_to_realworld]]. The function carries no decorators, raises no exceptions of its own, and has no external dependencies beyond the standard-library `datetime` module [[target/app/models/domain/rwmodel.py]].

## convert_field_to_camel_case

`convert_field_to_camel_case` is a utility function that converts a snake\_case string into a camelCase string [[target/app/models/domain/rwmodel.py::convert_field_to_camel_case]]. It accepts a single parameter, `string`, of type `str`, and returns a `str` [[target/app/models/domain/rwmodel.py::convert_field_to_camel_case]].

The function works by splitting the input on underscores, then rejoining the resulting words such that the first word is left entirely lowercase while every subsequent word has its first letter capitalised [[target/app/models/domain/rwmodel.py::convert_field_to_camel_case]]. For example, the snake\_case name `my_field_name` would become `myFieldName` [[target/app/models/domain/rwmodel.py::convert_field_to_camel_case]].

It carries no decorators, raises no exceptions, and has no external dependencies beyond Python's built-in string methods [[target/app/models/domain/rwmodel.py]].
